# 主机监控、数据库诊断与巡检

监控和巡检分别运行：监控页面展示采样与数据库诊断信息；巡检中心将只读执行包下发到关联主机，回收结果后生成 HTML 和 PDF。

## 主机监控

主机监控由 dfops 后端直接通过 HTTP(S) 读取现有 node_exporter，默认地址为 `http://主机地址:9100/metrics`，可以按主机修改。此链路不建立 SSH 连接、不下发执行包，也不要求 atop。SSH 仍用于巡检任务和日志文件接入。

主机管理中的“监控”提供 CPU、Steal、I/O 等待、每核使用率、可运行/阻塞任务数、内存、Swap、负载、磁盘容量与 inode、网卡吞吐及错误计数、磁盘吞吐、IOPS、读写平均时延、队列长度和设备忙碌时间。调度等待与 PSI 在 exporter 实际提供相应计数时显示，缺失项明确标为不可用。

支持单次采集或后台连续采集，间隔 30 秒、60 秒或 5 分钟。每轮两次 HTTP 读取间隔约 1 秒，用增量计算速率和时延；不把开机累计量当成当前使用率。请求有超时、响应大小上限和格式校验；失败时保留旧样本并显示采集错误，禁止回退为 SSH。关闭页面不影响已启用的后台采集。

采样保留 30 天。长时间范围返回最多约 600 个时间桶，每桶展示最后一个样本；缺失区间不补零，页面显示实际采样来源和最近样本时间。

## PostgreSQL 锁与慢 SQL 诊断

入口：数据库管理 → 锁与慢 SQL 诊断。数据库连接独立登记，也可以导入平台已有 PostgreSQL 连接。密码加密保存，接口不返回密码。

- 当前锁等待、直接阻塞者、根阻塞源、锁对象与等待起点：读取 `pg_stat_activity`、`pg_locks` 和 `pg_blocking_pids`。
- 当前执行超过 5 秒的 SQL：仅包含 `active` 会话，空闲事务显示最近一次 SQL，不将其时间当成当前 SQL 执行时间。
- 累计死锁：来自当前数据库的 `pg_stat_database.deadlocks`，同时展示统计重置时间。
- 历史慢 SQL、死锁详情和锁等待历史：从已有 PostgreSQL 日志增量采集。

诊断默认手动刷新，可选择 10/30/60 秒，仅页面打开时刷新。连接采用只读默认事务、5 秒语句超时和 1 秒锁超时；不会终止业务会话或修改数据库设置。当前会话最多 300 条、相关锁最多 500 条，达到上限会明确提示。

适用 PostgreSQL 14 及以上（使用 `pg_locks.waitstart`）。建议专用账号具备目标数据库 CONNECT 和 `pg_read_all_stats`；自动检测日志设置还需相应配置读取权限，例如 `pg_read_all_settings`。权限不足会显示提示，不把空结果当作无异常。

## 日志接入

在数据库连接中关联日志所在主机，点击“检测日志配置”，核对绝对目录、格式、时区与阈值，再启用日志接入。沿用数据库现有的 `log_min_duration_statement=5s`，平台不会修改 `postgresql.conf`，也不会重启 PostgreSQL。

优先使用 PostgreSQL CSV 日志。文本日志支持标准时间戳、PID 以及 DETAIL/HINT/CONTEXT/STATEMENT 多行关联；自定义前缀或不同语言日志可能无法完整识别，应通过原始日志核验。历史锁等待需数据库原已开启 `log_lock_waits`；未记录的事件无法补采。`pg_stat_statements` 的聚合统计不能替代逐次慢 SQL 日志。

后台约每 30 秒同步，单轮总读取上限 16 MiB，每文件最多读取 4 MiB；首次默认回溯 24 小时（可设 1～720 小时）。大日志按轮次追赶，可通过“读取进度”查看各文件已读字节及错误。读取游标和事件在同一事务提交，按文件设备/inode、截断代次、记录起始偏移去重，保留未完成的多行记录供下轮读取。支持重命名轮转和截断识别；源文件在读取前被删除的内容无法恢复。

页面提供时间、关键词、最低耗时筛选和分页，详情包含完整 SQL、账号、数据库、PID、客户端、应用、SQLSTATE、DETAIL/HINT/CONTEXT、原始日志和文件偏移。Parse/Bind/Execute 阶段分别保留，日志条数不等同于 SQL 执行次数。SQL 指纹当前为原文 SHA256，不是归一化模板。

日志事件保留 30 天。日志可能包含业务参数，应延用平台已有的账号访问管理与主机目录权限。

## 巡检中心与报告

支持手工批量选择主机和数据库，或配置每日定时计划。主机检查包括资源阈值和可选 systemd 服务；数据库检查包括实例身份、连接数、当前锁等待、当前慢 SQL、长事务、累计死锁，以及平台最近 24 小时已采集日志的统计和采集时效。

远端执行目录为登录账号私有目录，任务配置不出现在进程参数中，执行器读取后立即删除配置文件。执行包只读取资源与数据库状态；服务检查仅执行 `systemctl is-active`。

任务记录排队、下发、远端阶段、心跳、结果与错误；巡检并发上限 2。取消先发送标记，确认远端结果后再结束。SSH 中断后标记待核实，可读取原远端任务结果，不重复下发执行。平台重启通过租约恢复未结束任务。单个计划配置失效不影响其他计划，同一计划的上一轮未结束时跳过当日重复触发并显示原因。

采集结果和报告状态分别保存。检查完成可包含告警；权限不足、未配置日志或采集失败明确显示为未知。HTML/PDF 生成失败时，已采集结果仍保留，可单独重新生成报告。报告保存在工作空间 `operations/reports/run-编号`，下载需要平台认证。

PDF 使用原生 Go 排版和嵌入的 Latin 字体，并读取服务器上的中文 TrueType 字体；可用 `DFOPS_REPORT_FONT` 指定字体。兼容现有 DroidSansFallback 或 wqy-microhei 路径，无需 Chromium。缺少字体或字形时会显示报告生成失败，HTML 仍可下载。

## 编译与验证

使用 `bash scripts/build_dfops.sh` 构建。该脚本同时编译两个 Linux 架构的远端执行器、构建前端并嵌入主程序；直接 `go build ./cmd/server` 不保证包含执行器资源。

新增集成测试通过 `TEST_DATABASE_DSN` 指向可丢弃 PostgreSQL 数据库，`DF_ENCRYPT_KEY` 使用测试密钥。PDF 测试另需 `DFOPS_REPORT_FONT`。测试会建立测试表和锁等待，禁止指向业务数据库。

```sh
go -C backend test ./internal/opsprobe ./internal/pglog
go -C backend test ./internal/service -run '^TestOperations' -count=1
npm --prefix frontend run build
```

## 磁盘层级、读写时延与 CPU 竞争

设备信息完全来自 exporter。基础磁盘计数与文件系统容量兼容 0.18.1；新版导出 `node_disk_info`、`node_disk_device_mapper_info` 等字段时，可展示设备身份、LVM 名称并关联挂载目录。无法确认的映射关系写“未提供”，不猜测 dm-0 一定对应哪个分区。优先选择可确认的根目录设备，否则选择整盘；整盘、映射设备、RAID 和光驱分别标注。同一 I/O 可能经过多层，跨层不能相加。分区是否可见取决于 exporter 的采集过滤设置。

四张 I/O 图共用设备选择。读平均时延为读取耗时增量 / 完成读请求数，写平均时延同理，单位 ms；综合时延按完成请求数加权。该值包含块层排队与处理时间，不是 P95/P99。平均 I/O 队列为 weighted I/O time 增量 / 采样时长，在途 I/O 为采样结束时的瞬时计数。没有完成对应请求时显示“—”；旧样本未记录的新字段留空。忙碌时间占比不等于并行磁盘设备的性能上限。

CPU 使用率将 Steal 与实际执行时间分开。页面提供可运行任务数与核数对比、等待 I/O 的任务数、每核使用率、平均调度等待（等待时间增量 / 时间片增量）和 PSI some 在本次采样区间的等待比例。两次即时 HTTP 读取不能冒充内核的 10/60/300 秒 PSI 平均值。Steal 为内核记录的非自愿等待，0% 不能排除所有虚拟化调度争用；运行队列与负载也不能单独当作竞争率。CPU Ready 需要虚拟化宿主机侧数据。

字段定义参考 Linux 内核文档：[I/O statistics](https://docs.kernel.org/admin-guide/iostats.html)、[PSI](https://docs.kernel.org/accounting/psi.html)、[/proc](https://docs.kernel.org/filesystems/proc.html)。

## 巡检改造方案 待审核

依据桌面《HIS运维巡检操作指导书_V2.0.docx》（V2.0，2024-04-26），完整覆盖 cloudhis-1～39。手册提出每月巡检，报告面向医院信息科、实施和运维人员。以下为后续改造设计，尚未实施巡检重写。

现有报告的问题是缺少环境拓扑、完整业务检查目录、结构化证据和处置优先级。改造目标是使读者直接知道哪台主机、哪个集群或服务存在什么问题，风险是什么，证据在哪里，建议谁先处理哪一项。

### 判定规则

保留手册明确规则并允许按环境配置：服务日志目录超过 20 GB、Nacos 超过 7 个历史 access 文件、历史镜像建议每服务保留最新 2 个、归档保留 7 天、MinIO inode 使用超过 80%。这些形成报告问题项和建议，不自动清理或扩容。

时间线必须有前次基线才判断“发生变化”；复制延迟同时保留手册“Lag > 0”的记录要求，并通过可配置持续时长/字节/时间阈值区分瞬时追赶和持续异常。长事务按 xact_start 计算，当前 SQL 按 query_start 计算，不沿用 state_change 冒充运行时长。手册的慢 SQL Top5 是当前活动快照，历史 Top5 单独从已采集慢日志统计，两者不可混为一谈。

状态定义为正常、提醒、严重、未取得、不适用。缺工具、没权限、接口失败、超时、缺少历史基线分别记录原因；任何检查没取得证据都不能写正常。采集完成、规则判定和报告生成分别记录状态。

### 报告结构

1. 首页写医院/环境、巡检时间范围、版本、覆盖率（39 项中完成/异常/未取得/不适用）、整体结论、前三项优先处理的问题。
2. 问题清单按严重程度排序，每项包含影响、对象、证据摘要、阈值、首次/最近发生时间、责任角色、处理建议和详情定位。
3. 环境拓扑、主机资源与近阶段趋势、Kubernetes/应用状态、备份、PostgreSQL、MinIO 各有独立章节。用成员表、容量表、Top5、趋势图呈现，避免只列计数或重复根分区数据。
4. 每个检查项保留原手册编号，记录实测值、期望/阈值、结论、原因、建议和原始证据。完整 SQL/配置/命令输出进入可展开附件；账号密码和访问密钥脱敏。
5. 本次与上次对比时间线、备份新鲜度、复制延迟、容量、日志增长和每日对象增量。没有历史数据就显示尚未形成基线。
6. HTML 提供目录、状态/对象筛选和证据展开；PDF 为适合阅读和打印的结论、问题和表格报告。二者使用相同的结果快照，避免状态或统计不一致。

### 执行设计和验收

先按环境登记集群、数据库、MinIO、关联主机和备份目标，再创建覆盖环境的巡检任务；一个集群不按多个节点重复生成相同集群结论。资源趋势复用 HTTP 监控；Kubernetes/Patroni/MinIO/数据库优先走已有 API 或只读 SQL，文件和必须在服务器上执行的命令按任务下发。命令模板固定、参数校验，版本适配、采集预算、并发限制、错误证据和断点恢复独立实现。

先补齐 39 项检查定义及来源映射和样例证据，完成一份可审阅的报告样稿；审核通过后再开发采集器、规则及报告。验收至少包含正常集群、单点部署、备份过期、复制槽保留 WAL、持续复制延迟、阻塞/长事务、Pod OOM、日志过大、MinIO 节点/磁盘离线和指标缺失。未取得数据的检查必须出现在首页覆盖率和问题清单。
