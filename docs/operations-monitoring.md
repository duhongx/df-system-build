# 日常监控与巡检报告

监控中心用于查看日常运行状态，后台持续采集，打开页面自动展示和刷新。Linux 复用服务器管理的 node_exporter 配置、样本和图表；各组件按有效连接自动采集。PostgreSQL 的会话、锁与阻塞、慢 SQL 深入诊断复用数据库工作台；SkyWalking 保留主机服务管理入口。巡检报告汇总监控快照并独立存档。

## 使用方式

- 监控中心默认进入运行概况，列出纳管主机和组件实例的状态、关键值、实际采集时间及错误。分类页自动展示实例详情；页面每 5 秒读取数据，关闭页面不影响后台采集。
- 巡检报告 → 生成巡检报告：默认汇总全部纳管主机、已登记 PostgreSQL 和启用的组件连接的有效快照；缺失或过期项目按后台同一采集租约补采，冻结后在线查看或下载 PDF。
- Linux 主机：两个入口读取同一份主机样本和历史曲线，不依赖巡检任务或巡检结果。新纳管主机默认进入后台采集，保留已有的显式停用状态。
- 组件页：自动显示当前状态和最近 48 小时趋势；“立即刷新”仅是辅助操作，不负责启动监控。连接修改后旧快照及趋势失效，等待后台新样本。
- 环境配置 → 巡检组件连接：维护多个 Kubernetes、MinIO、Elasticsearch、Redis、RabbitMQ 实例。环境 Kubernetes 直接引用原配置；环境 PostgreSQL 接入工作台后引用原设置，不复制密码。工作台独立新增的连接仍独立维护。新增组件密码加密保存，接口不返回凭据。
- 服务器管理 → 服务管理：为 SkyWalking OAP、UI 等进程分别配置启动方式，维护人员可以启动、重启、核实状态和读取最近日志。

主机巡检固定包含 Linux 基础资源。执行器依据实际进程入口、已有 systemd 单元及关联连接识别组件，不要求维护人员逐次勾选执行范围。发现组件但无法取得访问权限、工具或证书时，保留具体缺口；未登记的远程组件不会被假定已检查。

MinIO 可以复用关联主机现有 mc 别名，也可维护独立端点和凭据；独立连接在主机私有临时目录中生成 mc 配置，执行 `mc admin info` 后删除，不覆盖已有别名。已有每日记录和备份目录均为可选项，不自行创建定时任务。

## 后台采集与时效

| 数据 | 默认周期 | 范围 |
| --- | --- | --- |
| Linux 运行指标 | 沿用原配置，默认 60 秒 | node_exporter HTTP；CPU、内存、磁盘/inode、网络和 I/O |
| PostgreSQL 运行指标 | 30 秒 | 当前连接、等待、慢 SQL、长事务及复制/归档；不执行整套指导书 SQL 或 SSH 扫描 |
| Kubernetes / Redis / RabbitMQ | 30 秒 | 对应只读 API / INFO；当前运行状态、关键计数和异常 |
| MinIO / Elasticsearch | 60 秒 | mc admin info / 只读集群接口 |
| 主机、日志、hprof、镜像、备份文件等专项 | 15 分钟 | 既有只读执行器，Kubernetes/MinIO 复用同一主机的专项快照 |
| PostgreSQL 指导书 SQL | 6 小时 | 完整原 SQL 和实际返回单独保留，不随页面轮询重复查询 |

采集按运行指标、主机专项及深度 SQL 分别限并发，使用数据库租约防止多个平台进程重复采集；失败自动退避并重试。运行指标失败时保留上次有效值并显示错误/时间，部分返回单独标为采集不完整。缺失区间不补零，无法访问不直接认定服务已停止。Pod 重启增量仅对连续样本中相同 UID 计算，新 Pod 或首次样本不伪造增量。

`monitoring_states` 保存当前采集状态和最近快照；`collection_samples` 的 live 层仅保存数值趋势，不每 30 秒重复保存完整 Pod 清单和 SQL 明细。两者的监控结果都受 48 小时限制。新增认证接口为 `/api/operations/monitoring`、`/monitoring/:kind/:id`、`/monitoring/:kind/:id/history` 和 `/monitoring/:kind/:id/refresh`。旧手动采集 API 保留兼容。

## 报告内容

报告有固定结构：范围和时间、整体结论、组件汇总、主机与各组件的关键结果、异常和采集缺口。组件页面和报告使用相同的结构化检查结果，不截取或拼接页面。正常结果汇总成表，异常展开；原始 SQL、命令与完整输出在已认证的检查详情中保留。容器运行时挂载不进入文件系统正文，Pod 累计重启与当前故障分开，长表只列关键行并说明总量。

新报告仅汇总本次实际纳入的检查内容；旧版指导书的其他项目不会被批量追加为“未执行”。已有报告继续使用原冻结快照；重新生成只调整展示，不重新采集。

每个对象在任务建立时保存应查清单。采集器没有返回的应查项目仍显示“未取得结果”，不能通过漏返回提高完成率。组件页面和报告按同一套检查项计算覆盖情况；同项在多个节点上的结果分别保留来源，任一成员缺结果都会形成缺口。

环境 Kubernetes 的连接版本包含实际 kubeconfig 文件内容。同路径替换文件或修改环境连接后，旧任务在发出请求前拒绝使用新目标；刷新来源后才能按新版本检查。巡检使用校验过的同一份配置创建独立客户端，保留文件中相对证书路径的语义。

| 本次对象 | 指导书项目 | 数据源与适用范围 |
| --- | --- | --- |
| Linux 主机 | 系统信息、CPU、内存、实际文件系统、部署识别 | SSH 只读执行器；根据实际部署追加组件检查 |
| PostgreSQL | 2、4、15～35，另列归档配置统计 | 原 16 条 SQL 与当前诊断；关联主机补充资源、部署方式、备份和归档文件 |
| Kubernetes | 1、6～14 | 当前实例 kubeconfig 的 Nodes/Pods；仅实际成员匹配的纳管主机补充日志、hprof、Nacos 和镜像 |
| MinIO | 3、5、36～39 | mc admin info、关联主机资源/inode、已有备份目录及逐日文件 |
| Redis | 运行、持久化与复制 | PING/INFO/CLUSTER INFO；不读取业务 key |
| Elasticsearch | 集群状态、节点资源 | 只读健康与节点统计接口 |
| RabbitMQ | 运行概况、节点及告警 | 只读管理接口 |

数据库的主机可按唯一地址匹配，也可在连接中明确关联；备份主机允许独立关联。多实例共用主机且没有明确备份目录时，主机级 pgBackRest 返回不能充作某个实例已取得备份。Kubernetes 逐节点匹配，不能因为登记了另一个集群就跳过当前主机的检查。关联主机的事实汇入相应组件结果，页面和报告均显示采集对象。

MinIO 从 `mc admin info` 的实际成员地址匹配存储节点；运行 mc 的管理机不自动视为存储节点。回环地址需要核实本地 MinIO 部署，无法唯一定位的成员保留资源缺口。

Java 日志和 hprof 从实际进程参数、工作目录及标准输出定位，不再以固定 `/opt/logs/prod` 为检查前提。PostgreSQL 归档配置/执行统计与归档文件目录分开；可识别的本地复制目录自动检查，脚本或远程归档无法定位时说明具体原因。单机无 Patroni、不存在本地业务 Java、pgBackRest 不适用平铺目录保留规则等情况须带事实理由列为“不适用”。目录读失败、权限不足、命令缺失和未关联主机保留明确缺口。

## 数据保存

临时组件结果、主机样本和 PostgreSQL 日志事件保留 48 小时，后台定期清理，读取接口按 48 小时限制返回。不会新增长期聚合数据。正式报告及其冻结结果、配置和服务操作审计独立保存，由用户主动删除报告，不随临时采集结果过期。

已有主机采集间隔及显式停用状态保留；启用的组件连接自动进入持续采集。PostgreSQL 日志接入仍沿用原启用配置。

历史定时巡检在报告页“已有定时任务”入口维护，可停用或删除。停用只阻止后续调度，当前任务与历史报告保留；不会新增默认定时任务。

## 服务管理

配置维护权归服务配置人及管理员，其他登录账号通过维护人员名单获得启动、重启和日志权限。配置人/主机创建人由现有平台账号记录确定，不引入任意命令执行表单。

- systemd：管理精确的 `.service` 单元。
- 脚本：维护工作目录、Linux 账号、该进程专用启动脚本、唯一的完整命令行参数和日志文件。按账号、真实工作目录及完整参数识别进程，避免匹配业务应用的 SkyWalking agent。
- 启动前检查是否已运行；重启先向匹配进程发送 TERM，确认退出后再启动；旧进程未退出则终止操作，不并行拉起，也不强制 kill。启动后核实进程持续存在，systemd 核实 active。
- 操作在后台执行并留审计；同一服务不能并发操作，执行期间不能修改或删除配置；SSH 中断或平台重启后标为待核实，不自动重复执行。短时间内结果未知时阻止重复下发。

仅支持纳管主机上现有的服务。虚拟机本身关闭时，进程管理入口不能替代虚拟化平台开机。接入前需核对服务器既有的 SkyWalking cron/自启脚本，避免多个控制入口互相重启；代码不会自行改写客户原有 cron。

## 完整本地自检

在仓库根目录执行：

```sh
python3 scripts/check_local.py --font /本机中文字体.ttf
```

也可设置 `DFOPS_REPORT_FONT` 后运行 `make -C backend test-local`。需要普通开发账号、Python 3.11 及以上、本地 PostgreSQL 工具（`initdb`、`pg_ctl`、`createdb`）、OpenSSL、Go、Node/npm，以及当前平台所需的 Linux CGO 交叉编译器；macOS 构建默认使用 Zig。前后端依赖需已安装。

脚本建立仅监听本机的临时 PostgreSQL，随机口令、SCRAM 认证和 TLS；每个数据库集成测试再使用独立数据库并清理连接。依次执行前端工作台测试、包含两种架构执行器的 Linux 构建及完整后端测试，结束后停止并删除临时数据库。日志、通过/跳过/失败统计、程序校验值和本地 HTTP 流程生成的 HTML/PDF 保存在 `output/selfcheck/时间-进程号/`，不入库。

脚本清除现场集群和 exporter 测试的启用变量，不执行部署。三个显式启用的现场测试（配置发布到 Kubernetes、前端集群发布、实际 exporter）默认跳过；这些跳过不能算作现场验收通过。历史报告排版另可用 `DFOPS_CONFIGURED_REPORT_SOURCE` 指定已有冻结结果，属于排版回归，不是重新巡检。PDF 下载与在线查看通过真实本地 HTTP 接口、后台调度、临时 PostgreSQL 和本地组件协议样本验证。

若直接运行数据库集成测试，`TEST_DATABASE_DSN` 必须指向可丢弃的本地测试集群，测试账号须能创建数据库和测试角色。不要指向业务环境；推荐使用上述脚本自动准备环境。

以下为既有采集与执行器的细节及历史实现记录。当前入口与自动范围以上文为准；旧巡检 API 保留用于历史兼容。

## 既有主机监控与执行器

监控和巡检分别运行。巡检报告按 HIS 指导书组织结论、问题、章节表格与证据；资源检查通过 HTTP 采集，数据库和可选服务检查使用关联主机上的只读执行包。回收结果后生成 HTML 和 PDF。

## 主机监控

主机监控由 dfops 后端直接通过 HTTP(S) 读取现有 node_exporter，默认地址为 `http://主机地址:9100/metrics`，可以按主机修改。此链路不建立 SSH 连接、不下发执行包，也不要求 atop。SSH 仍用于巡检任务和日志文件接入。

主机管理中的“监控”提供 CPU、Steal、I/O 等待、每核使用率、可运行/阻塞任务数、内存、Swap、负载、磁盘容量与 inode、网卡吞吐及错误计数、磁盘吞吐、IOPS、读写平均时延、队列长度和设备忙碌时间。调度等待与 PSI 在 exporter 实际提供相应计数时显示，缺失项明确标为不可用。

支持单次采集或后台连续采集，间隔 30 秒、60 秒或 5 分钟。每轮两次 HTTP 读取间隔约 1 秒，用增量计算速率和时延；不把开机累计量当成当前使用率。请求有超时、响应大小上限和格式校验；失败时保留旧样本并显示采集错误，禁止回退为 SSH。关闭页面不影响已启用的后台采集。

采样保留 48 小时。长时间范围返回最多约 600 个时间桶，每桶展示最后一个样本；缺失区间不补零，页面显示实际采样来源和最近样本时间。

## PostgreSQL 锁与慢 SQL 诊断

入口：数据库管理 → 锁与慢 SQL 诊断。数据库连接独立登记，也可以导入平台已有 PostgreSQL 连接。密码加密保存，接口不返回密码。

- 当前锁等待、直接阻塞者、根阻塞源、锁对象与等待起点：读取 `pg_stat_activity`、`pg_locks` 和 `pg_blocking_pids`。
- 当前执行超过 5 秒的 SQL：仅包含 `active` 会话，空闲事务显示最近一次 SQL，不将其时间当成当前 SQL 执行时间。
- 累计死锁：来自当前数据库的 `pg_stat_database.deadlocks`，同时展示统计重置时间。
- 历史慢 SQL、死锁详情和锁等待历史：从已有 PostgreSQL 日志增量采集。

诊断默认手动刷新，可选择 10/30/60 秒，仅页面打开时刷新。连接采用只读默认事务、5 秒语句超时和 1 秒锁超时；不会终止业务会话或修改数据库设置。当前会话最多 300 条、相关锁最多 500 条，达到上限会明确提示。

适用 PostgreSQL 14 及以上（使用 `pg_locks.waitstart`）。建议专用账号具备目标数据库 CONNECT 和 `pg_read_all_stats`；自动检测日志设置还需相应配置读取权限，例如 `pg_read_all_settings`。权限不足会显示提示，不把空结果当作无异常。

## 日志接入

在数据库连接中关联日志所在主机，点击“检测日志配置”，核对绝对目录、格式、时区与阈值，再启用日志接入。沿用数据库现有的 `log_min_duration_statement=5s`，平台不会修改 `postgresql.conf`，也不会重启 PostgreSQL。

优先使用 PostgreSQL CSV 日志。文本日志支持标准时间戳、PID 以及 DETAIL/HINT/CONTEXT/STATEMENT 多行关联；自定义前缀或不同语言日志可能无法完整识别，应通过原始日志核验。历史锁等待需数据库原已开启 `log_lock_waits`；未记录的事件无法补采。`pg_stat_statements` 的聚合统计不能替代逐次慢 SQL 日志。

后台约每 30 秒同步，单轮总读取上限 16 MiB，每文件最多读取 4 MiB；首次默认回溯 24 小时（可设 1～48 小时）。大日志按轮次追赶，可通过“读取进度”查看各文件已读字节及错误。读取游标和事件在同一事务提交，按文件设备/inode、截断代次、记录起始偏移去重，保留未完成的多行记录供下轮读取。支持重命名轮转和截断识别；源文件在读取前被删除的内容无法恢复。

页面提供时间、关键词、最低耗时筛选和分页，详情包含完整 SQL、账号、数据库、PID、客户端、应用、SQLSTATE、DETAIL/HINT/CONTEXT、原始日志和文件偏移。Parse/Bind/Execute 阶段分别保留，日志条数不等同于 SQL 执行次数。SQL 指纹当前为原文 SHA256，不是归一化模板。

日志事件保留 48 小时。日志可能包含业务参数，应延用平台已有的账号访问管理与主机目录权限。

## 巡检中心与报告

支持手工批量选择主机和数据库，或配置每日定时计划。主机检查包括资源阈值和可选 systemd 服务；数据库检查包括实例身份、连接数、当前锁等待、当前慢 SQL、长事务、累计死锁，以及平台最近 24 小时已采集日志的统计和采集时效。

远端执行目录为登录账号私有目录，任务配置不出现在进程参数中，执行器读取后立即删除配置文件。执行包只读取资源与数据库状态；服务检查仅执行 `systemctl is-active`。

任务记录排队、下发、远端阶段、心跳、结果与错误；巡检并发上限 2。取消先发送标记，确认远端结果后再结束。SSH 中断后标记待核实，可读取原远端任务结果，不重复下发执行。平台重启通过租约恢复未结束任务。单个计划配置失效不影响其他计划，同一计划的上一轮未结束时跳过当日重复触发并显示原因。

采集结果和报告状态分别保存。检查完成可包含告警；权限不足、未配置日志或采集失败明确显示为未知。HTML/PDF 生成失败时，已采集结果仍保留，可单独重新生成报告。报告保存在工作空间 `operations/reports/run-编号`，下载需要平台认证。

2026-10-28 报告入口调整为“在线查看”和“下载 PDF”，在线地址为 `/inspections/:id/report`。HTML 作为在线报告内容保留，通过认证请求读取并放在隔离的 iframe 中展示；页面不再提供 HTML 下载按钮。PDF 继续以附件下载。新任务默认名称统一为“系统巡检报告”；已有任务名称作为历史记录保留，接入验收任务名称不代表另一种正式报告类型。

任务执行、检查覆盖和报告生成分别展示。原存储状态 `PARTIAL` 不再直接显示“部分完成”：远端执行已结束时显示“检查已结束”；未确认远端是否结束时显示“远端执行状态待核实”。检查覆盖显示“已取得 X/Y 项结果、未完整取得 N 项、另有 M 项未执行”，并直接列出项目、对象及实际错误。PDF 生成失败单独显示，不冒充检查失败。列表与详情的检查统计优先读取已冻结报告，避免原始采集计数与报告项目计数混用；没有逐项快照的历史任务明确标注统计范围。覆盖接口仅返回摘要和缺口，不传输完整标准输出及结果表。

执行器 1.5.0 在已有检查范围内适配实际部署：主机命令检查同时采集 Linux 资源快照，省略 overlay 等重复运行时挂载，保留实际磁盘与 NFS 等持久存储，并合并同来源的重复挂载。关联的 PostgreSQL 连接在执行主机上只读核对物理复制、逻辑订阅及归档配置；缺少 `patronictl` 本身不会证明单机，也不再对已识别的原生 PostgreSQL 强制执行 Patroni 检查。发现 Patroni 进程、显式配置或服务单元时仍执行相应专项检查。归档未配置记录为需关注的配置事实，连接或权限错误保留为未取得结果。

Nacos 依据实际服务入口和进程命名空间识别，区分 systemd、Kubernetes、Docker 与普通主机进程，并读取每个本地实例的实际日志目录；不把使用 Nacos 客户端的 Java 应用误当作 Nacos 服务端。MinIO 默认执行 `mc admin info prod`，不再把客户端所有别名及示例站点写入报告；别名与管理凭据需真实有效。未接入逐日采样数据时明确记录配置缺项，不推算每日新增，不自行建立定时任务。缺少手填 PostgreSQL 备份目录时读取已有 pgBackRest 信息及本机常规 cron，区分历史备份与当前定时备份；此检查不推断外部调度器的配置。

HTML 在线正文与 PDF 从冻结结果派生精简展示，保留关键事实、缺口和异常，长表最多展示 10 行及关键列并注明数量；Pod、节点异常优先展示。原始命令、SQL、完整返回仍保存在冻结快照和任务检查详情中，生成精简报告不改写原始证据。已有巡检可重新生成版式，重新采集需新建任务；原来错误脱敏或缺失的结果不会在重新排版时补造。本轮部署适配仍以现有任务的检查范围为基础，尚未完成全部服务器、全部组件的自动发现入口。

PDF 使用原生 Go 排版和嵌入的 Latin 字体，并读取服务器上的中文 TrueType 字体；可用 `DFOPS_REPORT_FONT` 指定字体。兼容现有 DroidSansFallback 或 wqy-microhei 路径，无需 Chromium。缺少字体或字形时会显示报告生成失败，在线报告仍可查看。

## 磁盘层级、读写时延与 CPU 竞争

设备信息完全来自 exporter。基础磁盘计数与文件系统容量兼容 0.18.1；新版导出 `node_disk_info`、`node_disk_device_mapper_info` 等字段时，可展示设备身份、LVM 名称并关联挂载目录。无法确认的映射关系写“未提供”，不猜测 dm-0 一定对应哪个分区。优先选择可确认的根目录设备，否则选择整盘；整盘、映射设备、RAID 和光驱分别标注。同一 I/O 可能经过多层，跨层不能相加。分区是否可见取决于 exporter 的采集过滤设置。

四张 I/O 图共用设备选择。读平均时延为读取耗时增量 / 完成读请求数，写平均时延同理，单位 ms；综合时延按完成请求数加权。该值包含块层排队与处理时间，不是 P95/P99。平均 I/O 队列为 weighted I/O time 增量 / 采样时长，在途 I/O 为采样结束时的瞬时计数。没有完成对应请求时显示“—”；旧样本未记录的新字段留空。忙碌时间占比不等于并行磁盘设备的性能上限。

CPU 使用率将 Steal 与实际执行时间分开。页面提供可运行任务数与核数对比、等待 I/O 的任务数、每核使用率、平均调度等待（等待时间增量 / 时间片增量）和 PSI some 在本次采样区间的等待比例。两次即时 HTTP 读取不能冒充内核的 10/60/300 秒 PSI 平均值。Steal 为内核记录的非自愿等待，0% 不能排除所有虚拟化调度争用；运行队列与负载也不能单独当作竞争率。CPU Ready 需要虚拟化宿主机侧数据。

字段定义参考 Linux 内核文档：[I/O statistics](https://docs.kernel.org/admin-guide/iostats.html)、[PSI](https://docs.kernel.org/accounting/psi.html)、[/proc](https://docs.kernel.org/filesystems/proc.html)。

## 旧巡检 API 的指导书执行方式

使用场景是在客户环境开展节假日或季度等阶段性巡检，按需发起一次检查，汇总系统各组件本次运行情况，生成供客户了解系统和存档的报告。报告保留检查时间、执行对象、指导书项目、实际输出及执行错误；完整原始结果是存档内容的一部分。

依据桌面《HIS运维巡检操作指导书_V2.0.docx》，目标是登录对应服务器执行命令／SQL，记录结果并输出报告。已撤回此前额外增加的报告看板、机构／环境／主机用途表单、历史趋势依赖、环境参数基线及月度计划设计。

创建任务时选择平台已有主机与数据库，为每台主机选择它在指导书中承担的执行范围。只需补充命令所需的实际路径、命名空间、Nacos Pod、服务器已有 mc 别名、可选 Patroni 配置文件；数据库沿用已有连接与关联执行主机。新任务通过 SSH 下发执行包，在对应服务器执行；主机监控仍独立通过 HTTP 读取 node_exporter。

| 对应服务器／客户端 | 手册项目 | 执行内容 |
| --- | --- | --- |
| K8s 管理节点 | 1、7～10、13 | kubectl get nodes、kube-system/default/业务 namespace 的 pods、进入指定 Nacos Pod 查看 access 日志 |
| K8s 主机／node 节点 | 6、11、12、14 | top/free/df、服务目录 du、hprof 路径、crictl 镜像列表 |
| deploy 节点 | 14 | Docker 镜像列表 |
| PostgreSQL 主机 | 2、15～19 | 主机资源命令、patronictl list 的成员、角色、State、TL、Lag；填实际归档目录后仅当前 Leader 执行归档检查 |
| 当前 Leader | 19 | 先由 Patroni 成员和本机地址核验 Leader，以 postgres 身份执行 du，并记录归档文件时间、大小；按修改时间列出超过 7 天的文件 |
| PostgreSQL 备份服务器 | 4 | 备份目录文件清单、文件时间和大小 |
| MinIO 备份服务器 | 5 | 备份目录文件清单、文件时间和大小 |
| 已关联执行主机的数据库连接 | 20～35 | 执行指导书原有 16 条 SQL，包含表／索引膨胀 Top5 |
| MinIO 服务器 | 3、36～39 | 主机资源、df -i、mc config host ls、已有别名的 mc admin info、指导书 inode 计数命令 |

16 条 SQL 从原文提取，仅将不间断空格转换为普通空格，保存在 `backend/internal/opsprobe/manual_sql/`。保留原 SQL 的列名和筛选口径；报告不擅自以其他 SQL 或额外配置替代它们。登录数据库仍使用只读连接及查询超时，执行错误会原样记录并继续其余项目。

命令采用固定只读模板。Nacos 的交互式进入容器操作改为等价的非交互执行；日志大小保留完整 du 输出，镜像检查保留 Docker/CRI 列表以供核对。目录、Pod、namespace 和别名均作为参数校验与引用，不接受任意自定义 shell 命令。缺少工具、路径或权限时写明失败，不自动安装工具、改配置、清理文件或建立定时任务。

每项保存实际命令／SQL、执行服务器、开始／结束时间、标准输出、标准错误、退出码和是否截断；口令等凭据字段脱敏。相同命令支撑多个手册项目时复用同一次实际输出，例如 patronictl list 对应 2、16～18；不将其伪装成多次测量。每条命令最多 30 秒；命令输出与 SQL 返回完整保存，已移除 32 KiB／200 行截断，以及巡检结果回收的 8 MiB 和报告快照的 16 MiB 限制。执行中断、超时或权限错误仍保留已取得的内容和实际错误，不以成功结果代替。

“已记录待核对”表示执行成功并保存输出，不表示业务正常。指导书明确给出条件的项目才自动整理结果：节点 Ready、Pod 状态与重启、日志 20G、access 历史文件 7 个、镜像数量与每服务建议保留 2 个、Patroni running、TL 增长、Lag 大于 0、归档 7 天、inode 超过 80%、MinIO 节点／磁盘离线。SQL 20～35 只记录原查询返回；资源快照不另设健康阈值。

第 17 项使用同一 SSH 目标先前已归档的实际 TL 比较，不要求单独配置基线；首次记录没有前次值时明确说明。历史比较读取已冻结且 HTML 已生成的报告内容，后续修改目标原始数据不会改写比较依据。第 39 项保存本次 inode 数量及与上次巡检的区间净变化，区间变化不充作每日新增。填写客户已有每日记录文件时读取全部内容，按连续日期计算净变化；缺少、冲突、时间不明确或日期不连续时保留原文件并说明缺口，不补造统计。支持每行 `YYYY-MM-DD inode已用数`，或带零点 `00:00:00` 时间的记录。inode 净变化不代表精确病历／文书／签名业务新增。

`scripts/inspection_minio_daily.sh /实际绝对路径/daily-inodes.log` 提供指导书第 39 项的零点采样脚本：仅在服务器时间 00:00 执行、按日期追加、同日不重复覆盖。部署人员可按客户既定运维方式安排每天零点运行，再把输出文件配置给巡检；平台不会在客户服务器自行安装 cron 或软件。本轮没有向服务器部署该脚本。

报告保存本次结果快照，HTML／PDF 均从同一份已保存结果生成。报告先汇总 Kubernetes／应用、PostgreSQL／备份、MinIO／备份的各项运行情况和需关注内容，再按指导书列出明细和实际返回，附录保留 39 项执行情况。选定范围、未执行、不适用、采集失败分别标明；未选择的项目不混入采集失败计数。重新生成报告不会重新执行服务器命令；主动核实远端任务后更新结果快照。旧任务和已有计划记录保留兼容，本轮没有新增月度调度。
