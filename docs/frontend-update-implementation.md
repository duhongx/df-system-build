# 前端更新规则实施与验收

日期：2026-10-15。对应[完整规则](frontend-update-rules.md)，执行说明见[当前流程](vue-app-build-flow.md)。本轮调整 df-build-system 的更新代码，不替业务门户新增菜单或权限。

## 已实现

- 应用创建、编辑、制品提交和正式部署均核对身份与启用状态；编号唯一，cdn 保留，已有历史不能直接改变目标。纯制品登记允许没有 Git，新编号目录自动创建，已有目录必须有发布归属或显式接管。
- 主应用源码打包排除 apps；离线常规主包混入 apps 拒绝。显式 `.df-release.json` 整包清单绑定登记信息，拒绝重复来源，预览和部署记录按区域展开。
- 全 ZIP CRC、重复路径、越界与特殊文件检查，输入 SHA256 固定；源码生成 `.df-build.json`。HTML 解析支持无引号属性，检查入口脚本、本地引用和包内身份。
- 主、子、CDN、独立应用统一可信基线、文件清单、空间检查、过期基线及 ConfigMap 版本保护。未选区域、未知目录、CDN 和空目录保留，独立应用不读取共享基线。
- 保留旧文件；不可变资源同 URL 内容冲突拒绝。已有站点制作 C/F 两份镜像，推送后固定 digest；先资源、后入口，所有副本分别进行文件和 HTTP 验证。
- 发布前检查现网静态 404 和所选子应用路由，错误配置在镜像修改前停止。常规更新不覆盖已有 Nginx、Service、Ingress 等配置。
- 持久化 C/F 提交与验证阶段；失败不自动回滚，已提交事实保留。回滚拒绝较早批次覆盖后续发布，优先使用已验证的 C，复核所有副本及恢复内容。
- 流水线详情折叠展示实际区域和保留文件数量，详细错误仍在对应阶段日志中。

## 验证范围

本地相关 Go 回归和前端生产构建通过；数据库测试使用 150 上独立 PostgreSQL 容器及每个测试独立 schema，未连接生产库执行测试写入。测试凭据只存于远端受保护文件，未提交到仓库。

真实集群验收使用临时 namespace、两个副本及专用测试镜像标签，覆盖：新增 42、保留 CDN 与空 60、C/F 阶段、旧资源 URL、较早 42 批次不能覆盖后来 04 更新、最近批次兼容恢复、无 config.json 的 opm 独立更新和恢复。另验证错误静态回退在路由预检查中失败且不修改 Deployment 镜像。临时 namespace 和测试数据库在检查后清理；测试镜像标签保留用于追溯。

三个默认 Nginx 模板在隔离容器执行语法与 HTTP 检查，覆盖 04、gymk、42 深层路由、缺失 JS/CSS/JSON 的 404 和 404 缓存头。

安全导出的证据位于 [output/frontend-implementation-20261015](../output/frontend-implementation-20261015/)。上述技术验证不等于业务门户集成、租户权限或浏览器全部业务流程已验收，也没有以生产业务应用试发代替隔离测试。

## 运维边界与未提供能力

| 项目 | 当前行为 |
|---|---|
| 既有生产 Nginx / 自定义模板 | 不自动替换。旧的深层路由、静态回退或 404 缓存错误会被预检查拦截；需要明确的配置变更，保留 API 代理并保存恢复对象 |
| 旧 IMAGE_READY | 缺少新清单或阶段信息的旧任务需重新制作镜像，不能跳过检查直接发布 |
| 资源保留 / 清理 | 保守保留全部旧文件，覆盖 30 天和两个历史版本下限；尚无自动 GC，容量不足先停止 |
| 定向子应用回退 | 重新上传指定历史子包，基于最新基线创建新任务；尚无专用历史版本选择页面 |
| 互斥 | 单后端进程锁；多实例运行前仍需跨实例互斥 |
| 固定运行配置 / 环境字段合成 | 未实现通用兼容声明、环境字段合成或维护窗口编排；不兼容变更需要单独配置方案 |
| 动态加载与业务接入 | 平台不写业务菜单、权限或主应用注册；需由应用维护方验证加载协议与业务依赖 |

同 URL 的 SDK、JS、CSS 等资源变更会明确拒绝，不能通过重复上传或给 URL 加查询参数绕过；应先在业务项目中改为可并存的版本路径。
