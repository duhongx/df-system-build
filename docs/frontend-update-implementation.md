- 应用创建、编辑、制品提交和正式部署均核对身份与启用状态；部署审批同时固定登记 ID，删除后重建同名应用也不能复用旧审批。编号唯一，cdn 保留，已有历史不能直接改变目标。纯制品登记允许没有 Git，新编号目录自动创建，已有目录必须有发布归属或显式接管。

- 主、子、CDN、独立应用统一可信基线、文件清单、空间检查、过期基线及 ConfigMap 版本保护。本地环境持久完整目录按实际目标隔离，核对实际 ImageID，失效后重新同步；非本地环境直接从 Pod 导出。未选区域保留，独立应用不读取共享基线。
- 正式镜像的所选业务区域先清空再完整写入；CDN 同 URL 内容冲突拒绝。已有站点制作 C/F 两份镜像，C 临时预放资源，F 不保留所选业务区域的过期文件；推送后固定 digest，所有副本分别进行文件和 HTTP 验证。
- 发布前检查现网静态 404 和所选子应用路由，错误配置在镜像修改前停止。常规更新不覆盖已有 Nginx、Service、Ingress 等配置。
- 持久化 C/F 提交与验证阶段；失败不自动回滚，已提交事实保留。回滚拒绝较早批次覆盖后续发布，优先使用已验证的 C，复核所有副本及恢复内容。

## 运维边界与未提供能力

| 项目 | 当前行为 |
|---|---|
| 既有生产 Nginx / 自定义模板 | 不自动替换。旧的深层路由、静态回退或 404 缓存错误会被预检查拦截；需要明确的配置变更，保留 API 代理并保存恢复对象 |
| 旧 IMAGE_READY | 缺少新清单或阶段信息的旧任务需重新制作镜像，不能跳过检查直接发布 |
| 资源保留 / 清理 | 所选业务范围清空重建，未选范围保留；CDN 按版本目录增量更新。旧镜像不属于新站点文件，仍用于回滚 |
| 定向子应用回退 | 重新上传指定历史子包，基于最新基线创建新任务；尚无专用历史版本选择页面 |
| 互斥 | 单后端进程锁；多实例运行前仍需跨实例互斥 |
| 固定运行配置 / 环境字段合成 | 未实现通用兼容声明、环境字段合成或维护窗口编排；不兼容变更需要单独配置方案 |
| 动态加载与业务接入 | 平台不写业务菜单、权限或主应用注册；需由应用维护方验证加载协议与业务依赖 |

同 URL 的业务 SDK、JS、CSS 等资源允许随完整新包替换；这不保证旧页面兼容，更新后可能需要刷新。CDN 同路径冲突仍拒绝。
