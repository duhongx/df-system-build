# PostgreSQL 当前功能

核对日期：2026-10-14。普通 SQL 执行按 `df-ops-service` 的文件执行方式实现。[SQL 需求方案](sql-change-execution-requirements.md)和历史风险分析计划仅保留设计历史，不代表当前普通 SQL 执行行为。

## 配置与入口

- 环境配置维护 PostgreSQL 地址、端口、数据库名、管理员密码及统一业务密码，不需要填写业务用户名。
- 普通 SQL 使用文件名中的 schema 同名账号登录，并设置该 schema 为默认搜索路径；不使用管理员账号执行，不追加修改 owner 的 SQL。账号和 schema 需要事先存在。
- 与参考项目固定连接 `df_his` 不同，本项目沿用环境中配置的数据库名；必要配置缺失或读取失败时停止并记录具体错误。
- `/postgresql/instances` 展示全局配置的实例信息。
- `/postgresql/sql-execution` 提供普通 SQL 文件执行。
- `/postgresql/view-dependency-change` 保留独立的视图依赖变更工具，不参与普通 SQL 文件执行。

## 业务账号与密码

先选择业务用户的密码方式，页面和执行逻辑严格按选择区分：

| 密码方式 | 页面设置 | 普通 SQL 的密码选择 |
|---|---|---|
| 所有业务用户同一个密码 | 只填写一个业务密码，不显示账号密码配置表 | 所有业务账号只使用统一业务密码，忽略已保存的独立密码 |
| 业务用户密码不同 | 弹出账号密码配置窗口，自动获取业务账号并逐个设置密码；页面不显示统一密码输入框或账号表格 | 只使用对应账号的独立密码；未配置、解密失败或认证失败直接报错，不回退统一密码 |

- 默认选择“所有业务用户同一个密码”，数据库设置键为 `postgresql_password_mode=shared`；不同密码模式为 `individual`。同一密码输入后点击“保存并应用全部账号”，一次保存该密码及 PostgreSQL 连接设置；无需逐账号填写。切换方式不删除已有密码，只改变当前使用方式。
- 选择“业务用户密码不同”自动打开弹窗，也可通过“配置业务用户密码”再次打开。支持搜索、勾选、全选当前搜索结果、仅选尚未配置或填入密码的账号；选中若干账号后输入一次密码，点击“应用到选中账号”填入这些账号的待保存密码，其他账号保持原样。个别账号可在行内单独修改，批量填入后也可再修改某一行。
- 弹窗标注待保存数量，已保存密码不回显，空输入保留原密码。“保存并关闭”将所有待保存账号密码、当前密码方式及 PostgreSQL 连接设置在同一平台数据库事务中提交；任一保存失败整批回滚，并保留页面输入以便重试。无需再到页面底部保存密码方式。保留行内单账号保存／清除／测试；新密码未保存时不测试旧密码。关闭窗口清除尚未保存的输入。
- 大部分账号密码相同、少数不同的场景，选择不同密码模式，在弹窗批量填入大部分账号的密码，再单独修改少数账号，最后一次保存。两种模式依然严格区分，不增加统一密码回退。
- 连接测试明细使用独立弹窗展示，环境页面下方不展开账号或测试表格。上述保存只维护平台连接凭据，不执行目标库账号密码修改。
- 普通 SQL 从文件名获取 schema 同名账号，无需手填用户名。原有合法的非 `df_` schema 文件在统一密码模式下继续兼容，自动发现及独立账号密码维护面向 `df_` 业务账号。
- 管理员账号固定为 `postgres`，使用管理员密码进行实例查询、账号发现和独立视图依赖变更。普通 SQL 不使用管理员账号执行。
- “获取业务账号”通过管理员连接查询 `pg_roles`，只发现字面 `df_` 开头且允许登录的账号；已保存独立密码但当前目标库未发现的账号在独立模式下仍显示并标注“未发现”，可清除密码。
- 顶部“测试”先验证管理员，再按当前所选密码方式测试业务账号，逐项显示结果；独立密码模式下也可以单独测试某个账号。未发现业务账号时明确提示，不描述为业务账号验证通过。测试只检查登录和数据库连接，不执行业务 SQL，不代表所有业务权限已验证。
- 账号列表与测试结果不持久化，不自动创建账号或修改目标数据库密码。管理员、统一及独立密码以平台现有 AES-GCM 机制加密保存；独立密码列表不返回密码或密文。旧密码原值保留，旧单业务用户名设置不再使用。
- 机房及各客户现场独立维护各自的密码配置。备份时保留平台数据库和 `DF_ENCRYPT_KEY`；回退到不支持密码加密的旧程序时，需要同时恢复对应升级前平台数据库备份。

## 文件导入

支持上传一个或多个 SQL 文件、ZIP、粘贴完整 SQL，以及导入服务器上的 SQL／ZIP 文件。

文件名格式：`版本__排序号__schema.sql`，例如 `V2.0.0__001__his.sql`。也支持在 schema 后增加 `__说明`。版本、排序号、账号/schema 从文件名获取，不能用中文说明替代 schema。

导入只拆分 SQL 并记录原始行号，不执行风险分析、schema 自动补全或 SQL 改写。函数体、字符串中的分号由 PostgreSQL scanner 处理。错误文件名、无法拆分的内容在导入阶段报错；数据库对象是否存在及 SQL 执行错误在执行阶段返回。

- 文件记录保存版本、排序号、schema、完整内容及执行结果；语句记录保存行号、SQL、结果、执行人、时间、耗时、影响行数和 SQLSTATE。
- 待执行列表按版本、数字排序号、文件名排序；历史支持版本、schema 和文件名查询。
- 覆盖同名文件时，保留相同 SQL 的成功／跳过记录，按重复语句的出现顺序一一对应；修改过和新增的语句为待执行。旧文件保留为作废记录。
- 执行、覆盖、删除、跳过使用数据库事务锁；有效文件身份有唯一索引，并发操作不会生成两个有效副本。
- 执行中的文件不能覆盖、删除或手工跳过。包含执行结果待核实语句的文件不能覆盖或删除；已部分执行的文件删除后重新导入同名文件，仍继承其成功／跳过记录。
- 多文件和 ZIP 导入整体保存：其中一份无效时，不留下部分新文件。最多 500 个 SQL 文件，总内容最多 50MB。
- 服务器文件仅允许位于 `/opt/df-build-server`、`/root`、`/tmp` 下，校验真实路径。

## 文件执行

1. 选择一个已保存的文件，确认数据库、账号/schema、SQL 内容及三个跳过选项。
2. 点击“执行当前文件”，后台开始执行；离开页面或刷新不会取消任务。待执行列表包含运行中的文件，重新打开可继续查看进度。
3. 一个文件使用一个数据库连接，按原始行号逐句执行，最长每句 60 秒。普通脚本逐句自动提交，不提供文件级自动回滚。导入和执行均拒绝顶层 BEGIN、COMMIT、ROLLBACK、SAVEPOINT 等事务控制语句；函数体内的 BEGIN/END 正常支持。既有含事务控制的文件也不能执行，需要开发人员按逐句提交方式调整。
4. 已成功、已跳过的语句不再执行。每句执行前后保存记录，页面展示当前文件、语句序号、行号和结果。
5. 普通数据库错误立即停止当前文件，错误包含失败 SQL、行号、SQLSTATE 和原始错误；后续语句保持未执行。
6. 原因排除后重试原文件，只执行失败及未执行的语句。文件完成后禁止再次执行。

默认关闭三个自动跳过选项：字段已存在（42701）、对象已存在（42P07）、唯一约束冲突（23505 且错误文本包含 unique）。命中开启的选项时记为跳过并继续，否则立即停止。设置页维护默认值，文件执行前可以调整。

可停止后台执行：等待当前语句结束后，不再执行后续语句；停止不会撤销已成功提交的语句。如果连接中断或保存执行结果失败，无法确认结果的语句标记为“结果待核实”，不直接重放。服务重启也不会自动重跑中断的 SQL。核实已生效后可以手工跳过；未生效的 SQL 由开发人员提供新的修正文件。

提供文件／语句手工跳过、未成功文件删除、执行历史和完整 SQL 查看。普通页面与 HTTP 入口不再提供风险白名单、单句编辑／执行、自动补全和批次执行。多文件导入后逐个文件执行。

## 独立视图依赖变更

保留依赖分析、定义快照、预检查、删除／字段修改／重建／验证计划，以及任务和单对象恢复。该工具的管理员连接、事务／分步执行方式与普通文件执行独立。

分析、预检、执行、整体恢复、单对象恢复和校验共用任务状态锁。执行中不允许重新分析或预检覆盖备份；已成功任务及已有字段变更成功的任务不能重放，需核实并创建新的变更任务。

事务和分步模式都在专用连接上应用正数锁等待、语句超时及程序期限，执行结束销毁连接，避免会话配置污染连接池。分步删除阶段部分成功后遇错，只恢复已确认删除的对象；恢复记录对应固定的计划步骤，未执行步骤标注为未执行。事务回滚的步骤标注为已回滚。

服务中断、连接结果无法确定、结果记录保存失败，会保留字段变更待核实标记，禁止重放。可以使用备份恢复和校验依赖对象，但恢复视图不会清除字段变更的待核实标记；单对象校验／恢复也不会将整项任务误标为完成。管理员凭据变化会重建连接池。

恢复用于依赖对象，不是任意 SQL 或业务数据的通用回滚。SQL 文件也不会进入微服务镜像制作和滚动更新流程。
