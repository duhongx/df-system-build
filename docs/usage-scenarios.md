# 同一平台兼容机房与客户现场

同一套代码、同一个发布二进制分别部署到机房及客户现场，每套维护自己的服务器、数据库、镜像仓库、集群连接和历史。不需要分支维护两套系统，也不要求客户现场连接机房 Git 或安装编译工具。

## 使用场景

仅通过“系统设置 → 全局参数 → 部署环境”控制入口，不再设置独立的“使用场景”。

| 场景 | 入口和执行流程 | 需要的业务编译工具 |
|---|---|---|
| 本地 | 任务列表 → 创建源码任务 → Git 拉取 → 本机编译 → 制作/推送镜像；也支持制品更新 | 按应用安装 Git、JDK/Gradle/Maven 或 Node/Yarn/npm |
| 其他部署环境 | 新增更新任务 → 离线上传 JAR/ZIP → 应用匹配/校验 → 制作/推送镜像 | 不需要 |

滚动更新由“全局参数 → 部署环境”控制：`本地` 环境在镜像制作、推送成功后自动继续滚动更新；其他环境在“镜像制作完成”后单独提交滚动更新。该规则适用于源码与制品、Java 与 Vue 流程，源码编译仅在本地环境时开放。服务器、Kubernetes、SQL、制品管理、运行历史和人工回滚共用现有模块。现场仍需要平台 PostgreSQL、Docker/镜像仓库和目标集群等运行依赖；离线环境须预先准备基础镜像与离线资源。

执行开始时读取部署环境，本地流程在同一任务中继续执行，保留共享 web-main 的串行锁；任一阶段失败立即停止后续阶段，不自动回滚。已有 `IMAGE_READY` 历史记录保留手动滚动更新，不批量自动发布历史镜像。客户现场安装后应在部署环境中选择实际客户区域。

新安装的部署环境默认“本地”；客户现场必须改为实际客户区域。已有安装的部署环境和连接配置不自动覆盖。`customer_env` 为唯一入口依据，旧键 `deploy_source` 保留数据库记录但不再生效，接口不再读写该键。缺失或空白部署环境时关闭源码入口。

“新增更新任务”默认离线上传已编译 JAR/ZIP，支持服务器下载和选择已有更新版本。页面按“上传制品 → 应用匹配 → 制作镜像 → 滚动更新”分步显示，匹配阶段保留制品勾选，制作与更新阶段展示任务状态，日志从对应任务进入。上传后完成应用匹配和校验，再制作镜像并按部署环境继续更新；该流程不拉 Git、不编译源码。已提交任务的链接保留任务编号，刷新页面继续查看状态，不再次提交制品。

“制品管理”只保留“更新版本”和“制品库”：前者按一次上传/下载形成的版本管理文件、匹配、校验及部署记录，后者查看各应用最新或全部制品，并可进入所属更新版本。上传和发起更新统一在“新增更新任务”；原制品导入地址兼容跳转到此入口。

## 环境连接配置

Kubernetes 命名空间只在“系统设置 → 环境配置 → K8s 设置”维护，创建／编辑源码任务及制品更新不再填写或展示命名空间。新流水线统一读取环境配置，旧任务保存的覆盖值不再生效；已生成的历史流水线继续使用提交时保存的目标，避免更改待更新镜像的部署位置。未配置时仍使用 `default`。

镜像仓库、K8s、Nacos、SkyWalking、软件包下载服务器、PostgreSQL 六个区块均提供“保存并测试”：只保存当前区块，保存成功后使用同一份配置测试；保存失败不测试，测试失败保留已保存配置并提示失败。PostgreSQL 保留管理员及业务账号测试结果弹窗，页面底部“保存”仍可一次保存全部环境配置。K8s 保存按当前选择的服务器路径或手动录入方式生效，清除未选择方式的值。

## 编译配置

本地创建／编辑任务时，只选择应用即可自动带出默认编译配置，Java 使用 Gradle，Web 使用 Node；字段只读，任务请求无需 `buildConfigId`，后端按应用类型选择同一默认配置，切换应用同步切换。默认只从对应分类且启用的工具配置中选择，同类有多份时优先复用已有任务使用最多的配置，再按 ID 排序；停用配置、Java Maven 配置不参与 Java Gradle 默认选择。已有工具路径、环境变量和命令保留，新安装自动提供本机 Gradle／Node 默认值。没有启用的对应配置时明确提示，不能把错误类型或停用配置用于构建。

非本地环境隐藏源码任务、编译配置及 Git 字段，源码路由转到制品更新，后端也拒绝源码任务及编译配置写操作；历史记录、制品更新和手动滚动更新仍可使用。部署环境缺失、空白或读取失败时，前后端都不开放源码入口。

公共编译配置用于维护服务器工具路径、命令和产物目录，创建任务不需要重复设置。仅包含名称、Java/Vue 分类、安装命令、构建命令、产物目录、环境变量、说明和启用状态，所有命令在任务独立源码目录内由本机 Bash 执行。工具可用绝对路径调用；不同 JDK/Node 版本通过对应工具路径和环境变量配置。

Java 默认产物目录 `build/libs`，Maven 可设置为 `target`；Vue 默认 `dist`，也支持自定义输出目录。产物目录必须在当前任务源码目录内，前端不能选择源码根目录作为打包输出。

Docker 编译模式、编译镜像、CPU/内存限制、缓存挂载、旧执行器 API 和业务编译镜像文件已移除。已停用的旧容器配置归档，不再出现在编译配置列表中，也不参与默认配置选择；需要本机编译时新建本机配置。已有本机配置和历史任务引用保留。迁移保留旧数据库列和表，不再通过模型或接口使用这些编译容器参数。

## 业务发布版本

上传文件或目录、服务器下载目录均可携带 `version.json`，用于保存业务发布版本。`appVersion` 是业务版本号，必填文本，最多 128 个字符；`releaseTime`、`readme`、`featureList`、`appParamList` 及自定义业务字段可选。参考 [version.json 示例](../examples/version.json)。文件使用 UTF-8 编码，最大 1 MiB，每次导入仅对应一个 `version.json`。

更新记录列表展示业务版本、发布时间和更新说明，支持按业务版本、记录编号或说明搜索；详情及应用匹配页展示功能变更、参数说明、自定义业务内容和原始文件。参数说明兼容旧版 `paramName`／`paramDesc` 以及 `name`／`description`。也可以单独上传 `version.json` 保存业务版本说明。

业务版本号与上传记录编号分别保存。同一个业务版本多次上传会产生独立记录；后续刷新匹配或替换单个制品保留业务信息快照。重新上传会生成新记录；显式重新下载尚未提交的记录时，按本次选中的文件重新读取业务信息，避免套用本地缓存中旧的说明。历史记录和不携带 `version.json` 的制品继续使用现有流程；缺失业务版本不会影响更新，文件解析错误在页面显示。

业务清单中的参数、`fileList` 和更新方式作为原始信息保存，应用匹配、镜像制作和滚动更新沿用现有流程。单个应用的 `config.json`／`git.properties` 仍用于采集该应用自身的版本信息。

## 客户现场边界

客户现场隐藏源码任务和编译配置入口，源码路由重定向到制品更新；后端拒绝源码任务及编译配置写操作，Git 和编译阶段也检查部署环境，不能绕过页面执行源码构建。应用资产可不填 Git 地址，创建源码任务时才要求 Git 和可用编译配置。

已制作的镜像可在现场继续滚动更新，不重新拉取源码或编译。切换部署环境前应结束源码任务，运行中的源码阶段在进入 Git/编译时按当前部署环境检查；切换部署环境不撤销已提交的集群更新。

## 迁移与验证

192.168.1.150 保持本地环境，复用现有本机工具。客户现场部署相同二进制，选择实际部署区域，配置其镜像仓库、集群和制品来源即可。应用名称、Vue 角色/appCode、Dockerfile、启动脚本及部署模板仍需与业务系统匹配。

源码镜像采用 `/prod/app:分支-commit8-北京时间戳`。上传制品的 Git 元数据策略沿用当前制品流程，不以伪造提交号替代 Git commitid。业务可用性、滚动更新和回滚仍需各环境验收。

2026-10-14 已在 150 验证两种场景：源码流水线 3 完成真实本机 Java 编译及镜像推送；现场模式上传约 194 MB 的 JAR，制品流水线 4 完成镜像推送，没有 Git 或编译阶段。现场源码写接口返回 403，Chrome 验证菜单、路由和编译表单，最后恢复机房模式。旧表迁移及接口边界另用独立临时 PostgreSQL 数据库验证通过。未执行本轮滚动更新，未安装到真实客户服务器，详细记录见 [试点说明](pilot-192.168.1.150.md#本机编译与客户现场模式实测2026-10-14)。
