2. 只读确认 SkyWalking 实际进程、OAP/UI 专用脚本、运行账号、日志与既有 cron；按真实值配置服务管理。
3. 备份当前程序、运行配置及平台数据库结构，原子替换程序并核对健康、静态资源和迁移结果。
4. 发起新巡检，对照本次应查项逐项确认结果、缺口理由、节点来源；核对组件页与冻结报告一致，在线页与 PDF 可读。
5. 使用维护账号验证服务状态、启动/重启、日志和操作记录；确认无权限账号不能操作。

本地测试和历史报告排版不代表客户现场已验收。本阶段未执行部署或客户现场进程操作。

## 本轮开发收尾

上阶段仅有相关后端 114 项、前端 21 项专项测试通过。本轮补上真实本地 HTTP 流程：登记连接、实际请求本地组件接口、后台调度、结果落库、组件与报告统计一致、在线查看、PDF 下载、冻结后重新排版和拒绝未授权服务操作。

完整旧套件的 80 项顶层失败已逐步处理：测试连接池按生命周期关闭，各数据库集成用例使用独立临时数据库；SQL 执行配置引用实际测试连接，权限用例使用口令认证，取消对上一个用例残留表、角色和设置的依赖。旧断言按当前行为校正，保留路径、权限、前端资源及注册关系的校验。

完整回归还暴露并修复两个实际问题：嵌套目录里的前端包单独校验成功、组合校验失败；单条 SQL 重试收尾时，文件状态会短暂回到未执行。前者按实际输入解析并保留整组校验，后者通过事务原子更新文件汇总；均有回归用例。新增路径校验保证嵌套来源复制仍只使用展示文件名。

新增 `scripts/check_local.py`，或执行 `make -C backend test-local`，自动建立随机口令和 TLS 的本机临时 PostgreSQL，执行前端测试、Linux 构建及完整后端测试，结束后清理。具体条件见 [完整本地自检](../operations-monitoring.md#完整本地自检)。

2026-10-29 最终完整自检：549 项后端顶层测试通过，含子用例共 863 项，0 失败；前端 21 项及 Linux 构建通过。3 项现场测试（Kubernetes 配置发布、前端集群发布、实际 exporter）按设计跳过。SQL 重试状态、错误明细及真实 HTTP 报告工作流另通过 3 项 race 检查。最终测试集群使用全新的随机口令及 TLS，结束后已停止并删除。
