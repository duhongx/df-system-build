# PostgreSQL 当前功能

工作台更新日期：2026-10-28。SQL 变更发布沿用 `df-ops-service` 的文件执行方式。[SQL 需求方案](sql-change-execution-requirements.md)和历史风险分析计划保留设计历史；当前实现以下文说明为准。

## 数据库工作台

`/postgresql` 默认进入 `/postgresql/workbench`，采用统一连接上下文与对象导航。界面参考 [DMS 控制台配置](https://help.aliyun.com/zh/dms/configure-the-dms-console-based-on-your-business-requirements)和 [SQL Console](https://www.alibabacloud.com/help/zh/dms/manage-a-database-on-the-sqlconsole-tab)的工作区组织，慢 SQL 参考 [阿里云 PostgreSQL 慢日志分析](https://help.aliyun.com/zh/das/user-guide/slow-query-logs-7)的趋势、模板统计和样本明细联动。平台导航在数据库模块内默认折叠为图标栏，可独立展开；顶部直接切换数据库工作台、SQL 变更发布及视图依赖工具，不再叠加多层模块导航。原 `/postgresql/diagnostics` 地址重定向到工作台的锁诊断。

| 工作区 | 当前能力 |
|---|---|
| 连接与对象 | 登记具体的主机／端口／数据库／账号，管理日志接入；按 Schema 延迟加载表、视图、序列、函数与过程；查看列、主键、默认值、注释、索引、约束、触发器和对象定义 |
| 数据浏览 | 双击表／视图打开数据，支持查询列、绑定条件、排序、服务端分页和查看实际生成 SQL；对象右键菜单提供浏览、详情、SQL 窗口和复制入口 |
| SQL 窗口 | 多窗口编辑、语法高亮、已加载对象及列补全、选中 SQL 执行、JSON 数组绑定参数、PostgreSQL 格式化、预估计划、完整 CSV 导出；切换窗口保留光标、选择及撤销历史 |
| 结果集 | 已加载结果分页、搜索高亮／筛选、排序、列显隐、所选行／当前页／单元格复制、单行详情及 CSV；int8／numeric 排序不经过 JavaScript 浮点转换 |
| 我的 SQL | 按平台用户管理 SQL 收藏，支持当前连接或全部连接范围、搜索、编辑和载入；关闭的窗口可恢复草稿 |
| 工作区 | 按平台用户自动保存窗口、SQL、参数、连接版本和布局，刷新后恢复；保存失败保留当前内容，多页面并发修改时提示版本冲突并提供读取或覆盖操作 |
| 会话 | 当前库客户端会话、活跃／空闲事务／长事务筛选、账号与应用、等待事件、SQL 和事务开始时间 |
| 锁诊断 | 服务端递归补齐阻塞者，展示根阻塞源、多级关系、相关会话和锁对象；区分预备事务、不可见会话和快照环路；另有死锁及锁等待原始日志 |
| 慢 SQL | 按指定时间、关键词、阶段和耗时筛选已接入日志；按数据库、阶段、SQL 指纹聚合，展示趋势、总／平均／最大耗时、占比及最近五条真实样本 |
| 累计 SQL 统计 | 检测已有 pg_stat_statements，按总耗时／平均／最大／调用次数／共享块读取展示 Top 100，以及累计总量和统计重置时间 |
| 执行记录 | 保存平台操作人、当时的连接目标及版本、Schema、SQL、绑定参数、状态、耗时和返回行数；只在连接版本一致时允许直接打开到新窗口 |

SQL 窗口固定绑定创建时的连接版本。切换导航中的连接会选择或新建对应窗口；编辑／删除连接后，旧窗口停止执行并保留内容，不静默使用新目标。日志可能包含同一服务器上的其他数据库，打开样本前须找到主机、端口和实际数据库均匹配的已登记连接。

工作区在编辑停止约 800 毫秒后保存；Ctrl／⌘+S 立即保存，Ctrl／⌘+Shift+F 格式化选中 SQL 或全文。草稿与收藏存储在平台数据库的 `database_workspaces`、`database_saved_queries` 表，身份来自登录态；工作区不保存连接密码和查询结果，恢复草稿或载入收藏不自动执行。连接失效的草稿继续保留原目标和版本。未保存内容离开页面时提示，保存冲突不会自动覆盖其他页面。刷新可恢复文本与窗口；光标和撤销历史仅在本页切换时保留。

表数据每页 50／100／200 行，以主键作为默认排序或补充排序条件；没有主键且未指定排序时提示。每次翻页重新查询，不提供跨页一致性快照。筛选值通过绑定参数传入；“包含文本”按字面内容匹配 `%`、`_` 和反斜杠。序列只读取目录元数据，不调用 `nextval`；大整数属性以字符串传输。序列 `last_value` 在尚未使用或权限不足等情况下可以为空，缓存也会影响其含义，不能据此认定最后实际发放的编号。函数与过程按完整签名区分重载，只展示实际定义。

工作台每次接受一条 SELECT／WITH 或 SHOW，遍历 AST 拒绝写入 CTE、SELECT INTO 和行锁语句，并在 PostgreSQL 只读事务中执行。数据及结构变更仍从 **SQL 变更发布** 进入。只读事务遵循 PostgreSQL 本身的语义，不是对任意函数外部副作用的沙箱；连接账号应使用相应业务权限。预估计划支持 SELECT／WITH 以及 INSERT、UPDATE、DELETE、MERGE，使用 `EXPLAIN (FORMAT JSON, VERBOSE true)`，不执行 ANALYZE、不执行相应的数据变更，不把 Cost 描述为实际耗时。

结果网格默认预览 1000 行、最多 10000 行，明确标注是否还有后续结果。CSV 使用上次执行的 SQL、Schema 和参数**重新查询**并导出完整结果，在同一次只读事务中生成临时文件，成功后才提供下载；数据变化可能使两次查询结果不同。CSV 中 `\N` 表示 NULL，导出失败或超时时删除临时文件，不提供不完整 CSV。查询／导出可选 5、15、30 秒超时。这里的预览上限与巡检报告无关，巡检命令和报告原始输出继续完整保留。

会话与锁是实时快照，服务端短暂缓存 5 秒；已去除原有的会话／锁条数截断。SQL 文本仍受 PostgreSQL 的 `track_activity_query_size` 与统计权限约束；锁等待时长只使用可取得的 `pg_locks.waitstart`，不以 SQL 总耗时代替。快照中的环路不是已发生死锁的证明，死锁详情应查看数据库日志。PostgreSQL 13 无 waitstart 时显示时长未知。

慢日志记录数不等于全部 SQL 调用次数，Parse、Bind、Execute 和 Statement 分别统计；未开启接入、同步报错、未记录或已轮转缺失的日志都会影响覆盖范围。pg_stat_statements 是统计重置以来的累计数据，不受慢日志时间条件影响；扩展未启用或权限不足时明确提示，不自动安装扩展、修改参数或重启数据库。

本轮本地验证：真实 PostgreSQL 18，包含 305 个空闲会话的三级阻塞链、受限角色、参数化查询、带引号对象、1000 行预览／1307 行完整 CSV、导出超时、日志模板与阶段聚合、鉴权和连接版本校验。新增测试覆盖工作区并发保存、用户隔离、收藏版本校验、元数据及序列读取不推进编号；前端测试覆盖自动保存时序、冲突保留、网络失败重试、大整数排序及筛选值绑定。浏览器已检查查询、格式化、保存状态、结果高亮与筛选，以及此前的对象、预估计划、锁链与慢 SQL 页面。收藏弹窗和新增表数据浏览的完整交互尚未逐项完成浏览器验证；尚未在客户服务器验证本轮工作台。

## 配置与入口

- 环境配置维护 PostgreSQL 地址、端口、数据库名、管理员密码及统一业务密码，不需要填写业务用户名。
- 普通 SQL 使用文件名中的 schema 同名账号登录，并设置该 schema 为默认搜索路径；不使用管理员账号执行，不追加修改 owner 的 SQL。账号和 schema 需要事先存在。
- 与参考项目固定连接 `df_his` 不同，本项目沿用环境中配置的数据库名；必要配置缺失或读取失败时停止并记录具体错误。
- `/postgresql/instances` 展示全局配置的实例信息。
- `/postgresql/sql-execution` 提供与 df-ops-service 一致的文件列表及全屏 SQL 执行弹窗。列表分未执行／已执行文件，支持勾选多个文件、导入服务器文件、上传 SQL／ZIP、标记不执行和删除。弹窗左侧切换文件，右侧展示原始行号、SQL、状态和执行信息，底部调整跳过选项并执行。
- `/postgresql/view-dependency-change` 保留独立的视图依赖变更工具，不参与普通 SQL 文件执行。

## 业务账号与密码

先选择业务用户的密码方式，页面和执行逻辑严格按选择区分：

| 密码方式 | 页面设置 | 普通 SQL 的密码选择 |
|---|---|---|
| 所有业务用户同一个密码 | 只填写一个业务密码，不显示账号密码配置表 | 所有业务账号只使用统一业务密码，忽略已保存的独立密码 |
| 业务用户密码不同 | 弹出账号密码配置窗口，自动获取业务账号并逐个设置密码；页面不显示统一密码输入框或账号表格 | 只使用对应账号的独立密码；未配置、解密失败或认证失败直接报错，不回退统一密码 |

- 默认选择“所有业务用户同一个密码”，数据库设置键为 `postgresql_password_mode=shared`；不同密码模式为 `individual`。同一密码输入后点击“保存并应用全部账号”，一次保存该密码及 PostgreSQL 连接设置；无需逐账号填写。切换方式不删除已有密码，只改变当前使用方式。
- 选择“业务用户密码不同”自动打开弹窗，也可通过“配置业务用户密码”再次打开。支持搜索、勾选、全选当前搜索结果、仅选尚未配置或填入密码的账号；选中若干账号后输入一次密码，点击“应用到选中账号”填入这些账号的待保存密码，其他账号保持原样。个别账号可在行内单独修改，批量填入后也可再修改某一行。
- 弹窗标注待保存数量，已保存密码不回显，空输入保留原密码。“保存并关闭”将所有待保存账号密码、当前密码方式及 PostgreSQL 连接设置在同一平台数据库事务中提交；任一保存失败整批回滚，并保留页面输入以便重试。无需再到页面底部保存密码方式。保留行内单账号保存／清除／测试；新密码未保存时不测试旧密码。关闭窗口清除尚未保存的输入。
- 大部分账号密码相同、少数不同的场景，选择不同密码模式，在弹窗批量填入大部分账号的密码，再单独修改少数账号，最后一次保存。两种模式依然严格区分，不增加统一密码回退。
- 连接测试明细使用独立弹窗展示，环境页面下方不展开账号或测试表格。上述保存只维护平台连接凭据，不执行目标库账号密码修改。
- 普通 SQL 从文件名获取 schema 同名账号，无需手填用户名。原有合法的非 `df_` schema 文件在统一密码模式下继续兼容，自动发现及独立账号密码维护面向 `df_` 业务账号。
- 管理员账号固定为 `postgres`，使用管理员密码进行实例查询、账号发现和独立视图依赖变更。普通 SQL 不使用管理员账号执行。
- “获取业务账号”通过管理员连接查询 `pg_roles`，只发现字面 `df_` 开头且允许登录的账号；已保存独立密码但当前目标库未发现的账号在独立模式下仍显示并标注“未发现”，可清除密码。
- 顶部“测试”先验证管理员，再按当前所选密码方式测试业务账号，逐项显示结果；独立密码模式下也可以单独测试某个账号。未发现业务账号时明确提示，不描述为业务账号验证通过。测试只检查登录和数据库连接，不执行业务 SQL，不代表所有业务权限已验证。
- 账号列表与测试结果不持久化，不自动创建账号或修改目标数据库密码。管理员、统一及独立密码以平台现有 AES-GCM 机制加密保存；独立密码列表不返回密码或密文。旧密码原值保留，旧单业务用户名设置不再使用。
- 机房及各客户现场独立维护各自的密码配置。备份时保留平台数据库和 `DF_ENCRYPT_KEY`；回退到不支持密码加密的旧程序时，需要同时恢复对应升级前平台数据库备份。

## 文件导入

支持上传一个或多个 SQL 文件、ZIP、粘贴完整 SQL，以及导入服务器上的 SQL／ZIP 文件。

所有 SQL 文件均可先上传，包括中文说明文件名、空文件、带人工处理说明的文件。`版本__排序号__schema.sql` 是自动识别约定，例如 `V2.0.0__001__his.sql`，也可在 schema 后增加 `__说明`。不符合约定时保留原文件名和完整内容，不推测数据库账号；能识别的版本及排序号仍保留，无法识别的 schema 留空。

导入尝试拆分 SQL 并记录原始行号，不执行风险分析、schema 自动补全或 SQL 改写。函数体、字符串中的分号由 PostgreSQL scanner 处理。无法识别账号/schema、空内容、无法拆分或含不支持的事务控制语句时，仍保存文件，以 importMessage 展示待处理原因。文件名及内容不会为通过校验而自动修改。可查看完整原文件、标记不执行或删除。

- 文件记录保存版本、排序号、schema、完整内容及执行结果；语句记录保存行号、SQL、结果、执行人、时间、耗时、影响行数和 SQLSTATE。
- 待执行列表及勾选文件的执行顺序均按版本、数字排序号、文件名、ID 排序；历史支持版本、schema 和文件名查询。新上传文件记录实际上传人；旧记录没有上传人时显示“—”。
- 覆盖同名文件时，保留相同 SQL 的成功／跳过记录，按重复语句的出现顺序一一对应；修改过和新增的语句为待执行。旧文件保留为作废记录。
- 执行、覆盖、删除、跳过使用平台数据库事务锁；有效文件身份有唯一索引，并发操作不会生成两个有效副本。
- 执行中或队列等待中的文件不能覆盖、删除或手工跳过；其他执行请求不能占用这些文件。包含执行结果待核实语句的文件不能覆盖或删除；已部分执行的文件删除后重新导入同名文件，仍继承其成功／跳过记录。
- 多文件和 ZIP 导入整体保存；不因某个文件的命名或 SQL 内容无法执行而拒绝其余文件。仍校验实际 SQL 文件类型、同名冲突、文件总数和大小，平台保存失败时整批回滚。最多 500 个 SQL 文件，总内容最多 50MB。
- 服务器文件仅允许位于 `/opt/df-build-server`、`/root`、`/tmp` 下，校验真实路径。

## 文件执行

1. 所有 SQL 文件先上传到列表。不满足执行条件的文件显示“待处理”及原因，用户可先标记不执行或删除。选择文件并确认 SQL 内容及三个跳过选项。
2. 提交执行时，后台过滤无法识别账号/schema、空内容、无法拆分或含不支持事务语句的文件，仅将其余文件纳入执行队列；返回过滤文件清单和原因。被过滤的文件保持未执行，不自动标记为永久跳过，也不阻塞其余文件。全部文件都被过滤时不创建执行队列。
3. 列表勾选文件后点击“执行SQL文件”打开执行弹窗，再点击底部“执行”。后台按顺序执行所选文件；关闭弹窗、离开页面或刷新不会取消队列。未执行列表包含运行和等待中的文件，点击这些文件可重新打开整个执行队列。真实失败或停止操作会终止后续文件，等待文件释放为未完成状态，允许之后重新选择执行。
4. 一个文件使用一个数据库连接，按原始行号逐句执行，最长每句 60 秒。事务外语句逐句自动提交。顶层 `BEGIN` / `START TRANSACTION` 到对应 `COMMIT` / `END` 或 `ROLLBACK` / `ABORT` 被识别为显式事务组，在文件的同一连接中执行并保留 BEGIN 的事务选项。组内完成的语句先显示“待提交”，仅在 COMMIT 确认成功后标记成功；失败或停止时整组回滚，分别显示失败位置、已回滚与未执行。脚本主动 ROLLBACK 的组显示已回滚，不记为成功写入。函数和 DO 体内的 BEGIN/END 不参与顶层分组。既有文件按保存的 SQL 动态识别，无须重新上传。
5. 已成功、已跳过的语句不再执行。每句执行前后保存记录，页面展示当前文件、语句序号、行号和结果。
6. 普通数据库错误立即停止当前文件，错误包含失败 SQL、行号、SQLSTATE 和原始错误；后续语句保持未执行。
7. 原因排除后重试原文件，只执行失败及未执行的语句。文件完成后禁止再次执行。

跳过选项缺省开启，保留设置页已保存的开关值，执行前可调整。按 SQL AST 和 SQLSTATE 限定匹配范围，不依赖错误消息语言：

- 纯粹由多个 `ADD COLUMN` 组成的 `ALTER TABLE` 自动按字段拆分，每个字段单独记录结果；使用 PostgreSQL AST，保留类型精度、默认值、表达式和带引号名称中的逗号。混合其他 ALTER 操作的语句和 DO/函数体不自动拆开。单项字段已存在（42701）受字段跳过选项控制，跳过后继续其余字段；SQL 自带 `IF NOT EXISTS` 时保留其跳过语义并记录为“跳过”。其他错误仍按普通执行规则处理。
- 原有 `BEGIN/COMMIT` 边界保留，拆出的字段仍在同一个事务组内；已有字段通过内部保存点恢复后跳过，真正的错误使整组回滚。新上传、编辑和已上传的可修改记录均支持自动拆分；已完成或结果待核实的记录不重置，手动暂缓的记录仍保留失败，须单独重试。原 SQL、旧错误和拆分来源保留在审计中，拆分自身不执行业务 SQL。
- 单项命名 `ALTER TABLE ADD CONSTRAINT` 返回重复对象（42710）时，受“表／索引／约束已存在”选项控制：确认约束属于目标表且定义一致才跳过。外键解析引用表的实际 OID，并比较字段、引用字段、更新／删除规则及延迟属性；未验证约束不能充当本次要求的已验证约束。定义不同或无法确认等价时保留原错误与校验说明，不自动删除／重建约束。
- `CREATE TABLE` 或 `CREATE INDEX` 同名对象已存在（42P07），受表／索引／约束跳过选项控制，不自动校验已有定义。
- `INSERT` 主键／唯一约束冲突（23505），受唯一冲突跳过选项控制，适用于单条配置数据插入。
- 单个 `DROP VIEW` 的目标不存在（42P01）继续；权限或依赖错误停止。建议脚本显式使用 `IF EXISTS`。
- 创建／替换视图失败、创建唯一索引的数据冲突、UPDATE／DELETE 失败及其他错误均停止当前文件和后续所选文件。显式事务组内的 DROP 随整个事务回滚；事务外相邻同名 DROP VIEW + CREATE VIEW 由既有视图组合事务处理。其他此前已提交的独立语句保持原结果。

跳过有独立记录，不记为成功；重试继续保留成功及跳过的语句。显式事务中的自动跳过使用内部保存点恢复事务，再核实索引状态等条件；其他错误整组回滚。事务组的手动标记失败、不执行、失败重试作用于整个组，组外语句不随单独重试执行。编辑组内失败/未执行 SQL 会重置整个未提交组，后续从 BEGIN 重试。覆盖上传仅沿用内容完整一致且整体完成的事务组，不能按单句继承部分成功。

执行窗口的当前文件上方提供“整文件标记失败”：将未执行及失败的语句统一标记为手动失败并暂缓，加入当前失败 SQL 清单；不提交业务 SQL，也不自动执行后续文件。已成功、已跳过、已关联视图任务的语句保持原状。原错误保留，每条新标记记录 `FILE_FAIL` 操作及 `submitted=false`，重复标记不重复创建逐句记录；原执行批次快照保留。执行中、结果待核实、事务边界无效或事务组仅部分可处理时拒绝操作。可通过“查看本文件失败 SQL”按文件 ID 精确定位，清除文件筛选后查看全部失败。该操作只批量标记处理状态；合并执行使用“整文件转入视图依赖”或多选转入。

可停止后台执行：等待当前语句结束后，不再执行后续语句；尚未提交的显式事务组整体回滚，已提交的语句保持原结果。如果连接中断或保存执行结果失败，无法确认结果的语句标记为“结果待核实”，不直接重放。服务重启也不会自动重跑中断的 SQL。核实已生效后可以手工跳过；未生效的 SQL 由开发人员提供新的修正文件。

提供文件／语句手工跳过、未成功文件删除、执行历史和完整 SQL 查看。普通页面与 HTTP 入口不提供风险白名单、单句执行、自动补全。SQL详情允许编辑未执行或失败的原始语句片段（完整 DO 块计为一条）。片段因缺少分号而误含多条 SQL 时，可以补充分隔符修正拆分：首句保留原记录 ID，新增语句创建新记录并关联来源，均设为未执行；原错误和修改前后内容保留在审计中。保存同步完整文件与后续行号，并保留其他语句已有的成功／跳过结果。拆分后不会自动执行，需点击执行继续。已成功、已跳过、执行中、排队中或结果待核实的记录不可编辑；并发修改会拦截旧版本覆盖。保存不会执行 SQL，需点击“执行”重试，继续跳过既有成功和已跳过的语句。 失败信息直接显示在对应语句的执行信息列并标红，打开文件或队列执行失败时自动定位错误行；顶部“定位错误”可再次跳转，多文件失败会定位实际失败文件。语句已有错误结果时不再重复展示顶部整段 SQL 错误；连接认证等没有语句结果的文件级错误仍保留提示。`POST /postgresql/sql-files/execute` 接收 fileIds 和 options，原子占用所选文件并启动后台顺序执行，不改写原有导入批次。队列结果由现有批次查询接口读取。事务外逐句自动提交，显式事务按组提交。

## 执行记录、跳过与历史查询（2026-10-16）

`sql_change_statements` 保存最新状态，供续跑判断；`sql_statement_records` 保存每次执行尝试与手动操作，重试和跳过不会覆盖旧记录。成功或已跳过的业务 DDL/DML 不会重新提交数据库。`sql_execution_file_snapshots` 保存每次所选执行批次的文件及原始语句状态，查询历史批次时叠加该批次独立的执行记录；后续修改、跳过、重试、删除或覆盖文件均不改写旧批次。沿用既有结果会标为“沿用历史结果”，不会算作本次重新执行。

续执行的新连接按原顺序恢复已成功的 `SET/RESET`（包括 `search_path`），以 `SESSION_RESTORE` 单独记录，不覆盖原语句的成功状态。手动跳过的配置不会恢复；恢复失败就停止，不提交后面的业务 SQL。`SET LOCAL` 与 `SET ... FROM CURRENT` 无法保证续执行语义，允许上传但执行前提示改为明确的会话配置。

SQL 新连接以“文件 schema + 该连接原有的 search_path”初始化搜索路径，保留数据库／账号配置中的 `public` 或扩展 schema。旧逻辑仅保留文件 schema，会使 `uuid_generate_v1()` 等未限定 schema 的函数在网页中不可见，而 psql 默认连接可能正常。普通执行、续执行和切换账号重试共用此初始化；脚本显式 `SET/RESET search_path` 仍按原顺序执行／恢复。若 psql 与网页使用不同账号、数据库或账号缺少对象权限，仍需核对连接与授权；不会自动创建扩展或更换执行账号。

批次完成后通过弹窗展示当次成功、失败、跳过与未入队统计，不在执行窗口顶部常驻成功提示；打开既有完成记录不会再次自动弹窗。失败或中断仍保留简短状态与定位入口，具体 SQL 错误保留在语句执行信息和详情里。

文件及进度按连接主机、端口、数据库与 schema 归属；密码变化不重置进度。不同库可以存在同名文件，覆盖上传只继承当前库的进度，切回原库仍保留原进度；待执行／已执行文件列表只展示当前目标与尚未绑定的文件，历史记录仍可查询全部目标。队列占用和实际连接时检查目标，连接配置改变后不会把旧队列提交到新库。新增 `database_target` 字段与对应的有效文件唯一索引。升级时优先依据已有执行记录绑定旧文件；没有目标记录的旧文件以升级时连接作为一次性基线，不补造历史审计中的数据库信息，因此升级前应保持原有数据库连接。出现多个已记录目标的旧文件保留为不确定归属，不能自动复用。

覆盖导入后按继承的语句明细汇总文件状态：全部成功或成功与跳过混合时为“成功”，全部跳过时为“已跳过”，直接进入已执行文件列表；有新增或未完成语句时仍为“未执行”，再次执行只提交剩余语句。文件消息标明沿用历史结果；全部完成时展示原语句的最近处理人和时间，不将上传人、上传时间记作执行人和执行时间。服务启动会修复此前因重复导入而遗留的“明细已完成、文件未执行”记录，不执行业务 SQL，也不改写历史执行批次和审计。

创建索引返回“已存在”时，必须确认索引属于目标表且 `indisvalid`、`indisready`、`indislive` 均为真，才允许自动跳过；正常成功返回和 `IF NOT EXISTS` 也检查命名索引的有效性。并发创建失败留下的无效索引不会被判为成功，也不会自动删除或重建。

记录包含 SQL 原文、文件及行号、执行账号、目标数据库、操作人、开始／结束时间、状态、SQLSTATE、影响行数、耗时，以及操作前的错误及状态。`action=EXECUTE` 是执行尝试，`AUTO_SKIP` 是提交后因重复错误自动跳过，`MANUAL_SKIP`／`FILE_SKIP` 是手动跳过，`EDIT` 是编辑，`AUTO_SPLIT` 是按新增字段自动拆分（未提交业务 SQL），`CONFIGURE` 是执行配置，`INHERIT` 是覆盖上传后沿用既有结果。`submitted=true` 表示已提交数据库处理，不表示执行成功；必须结合 `status` 判断。手动跳过本次 `submitted=false`，此前仍可能存在失败或结果待核实的执行尝试。

旧版仅保留最后状态，升级后以 `LEGACY_SNAPSHOT` 迁移，`submitted=null`，不伪造已丢失的历史。旧版手动跳过来源可从已有消息识别并标注。旧执行批次没有历史快照时明确提示无法还原，不能用当前成功状态冒充过去的结果。

页面“SQL记录”支持按 SQL 关键字、文件、账号/schema、操作和状态查询；单句详情中的“执行记录”会追溯同名覆盖上传所沿用的原始执行记录。执行批次可查看当次文件及 SQL 结果。API：`GET /postgresql/sql-records`；筛选 `statementId`、`fileId`、`batchId`、`sqlHash`、`keyword`、`fileName`、`schemaName`、`action`、`status`。`GET /postgresql/sql-batches/:id` 默认读取历史快照，`current=true` 仅供续跑工作台读取文件当前状态。

平台数据库中可按 SQL 内容查询，例如：

```sql
SELECT id, batch_id, file_name, line_number, action, skip_kind,
       status, submitted, operator, started_at, sql_state, message
FROM sql_statement_records
WHERE sql_content ILIKE '%v_zhuyuanyz_zl%'
ORDER BY id;
```

跳过保存及刷新完成之前禁用执行入口。`POST /postgresql/sql-batches/:id/cancel` 持久保存整个执行批次的停止请求，在语句／文件边界检查；等待当前语句完成，不撤销已经提交的结果。请求不再依赖页面缓存的旧文件 ID。

缺少 schema 的文件可通过“执行配置”补填账号/schema（`PUT /postgresql/sql-files/:id/execution-config`），先只读校验账号连接、schema 存在及 USAGE 权限，不执行上传 SQL。文件已有语句结果后禁止切换账号；配置会在同名覆盖上传时保留。版本及文件序号采用自然数字顺序，列表、工作台和实际执行一致（V2 在 V10 之前）。

## 独立视图依赖变更

保留依赖分析、定义快照、预检查、删除／字段修改／重建／验证计划，以及任务和单对象恢复。该工具的管理员连接、事务／分步执行方式与普通文件执行独立。

批量字段通过一次 catalog 查询生成联合依赖图，按最大依赖深度固定删除和重建顺序，同一个视图只备份一次。依赖图查询与每个视图的权限、注释、索引等元数据备份分别限时，避免几百个对象共用已经耗尽的 10 秒期限；仍响应上层取消。分析和执行前核对期间会保存当前对象及进度，页面可持续读取。

失败页面固定显示“错误详情”，优先展示 FAILED／UNKNOWN 步骤的原始错误，再单独展示回滚或自动恢复结果；不再把前面步骤的“已回滚”当作原始失败原因。详情包含失败阶段、完整执行批次 SQL、对应原始字段 SQL 和行号，以及服务端可提供的 SQLSTATE、DETAIL、HINT、CONTEXT，可一键复制。分析接口失败后也会重新读取已保存状态；已保存的失败任务可直接打开查看，无须重跑 SQL 获取错误。数据库结果不确定时继续禁止重放。

`POST /postgresql/view-dependency-tasks/:id/execute` 预检并占用任务后返回 `EXECUTING`，实际变更在后台执行；调用方通过 `GET /postgresql/view-dependency-tasks/:id` 查询最终结果，不能将提交成功当作执行成功。页面约每 2.5 秒串行刷新阶段、已完成列数、当前 SQL 和耗时，URL 的 `taskId` 用于刷新后继续查看。离开或刷新页面不会取消已提交的字段变更；服务进程中断仍按结果待核实处理，不自动重放。

连续、同表且互不依赖的单列类型变更合成一条多列 `ALTER TABLE`，执行和导出使用同一合并规则。保留原表顺序、重复修改同列的先后关系、标识符大小写及 ONLY 语义；跨列引用或函数等复杂 `USING` 表达式维持逐句执行。合并批次在数据库内原子生效，其中一列失败则整批不提交。原始字段 SQL、行号和顺序仍逐列保存，`execution_step_id` 关联实际批次并同步状态；事务内完成但未提交的列标为 `APPLIED`，回滚后标为 `ROLLED_BACK`。手动恢复视图追加步骤审计，保留原执行结果。

分析、预检、执行、整体恢复、单对象恢复和校验共用任务状态锁。执行中不允许重新分析或预检覆盖备份；已成功任务及已有字段变更成功的任务不能重放，需核实并创建新的变更任务。

顶部、依赖对象列表和备份详情中的恢复按钮使用同一规则：成功、尚未执行、预检失败或已恢复的任务禁用；仅执行失败、恢复失败、校验失败或结果待核实且存在备份的任务允许恢复。后端在取得任务锁后再次校验，整体和单对象恢复接口不能绕过成功状态限制。

事务和分步模式都在专用连接上应用正数锁等待、语句超时及程序期限，执行结束销毁连接，避免会话配置污染连接池。分步删除阶段部分成功后遇错，只恢复已确认删除的对象；恢复记录对应固定的计划步骤，未执行步骤标注为未执行。事务回滚的步骤标注为已回滚。

服务中断、连接结果无法确定、结果记录保存失败，会保留字段变更待核实标记，禁止重放。可以使用备份恢复和校验依赖对象，但恢复视图不会清除字段变更的待核实标记；单对象校验／恢复也不会将整项任务误标为完成。管理员凭据变化会重建连接池。

恢复用于依赖对象，不是任意 SQL 或业务数据的通用回滚。SQL 文件也不会进入微服务镜像制作和滚动更新流程。

### 显式事务支持边界

- 支持完整的 BEGIN/START TRANSACTION 到 COMMIT/END、ROLLBACK/ABORT，可与事务外语句、多组事务混合。
- 不完整事务、嵌套 BEGIN、SAVEPOINT/ROLLBACK TO、两阶段事务及 AND CHAIN 暂不支持，整份文件在执行前给出具体行号并过滤，不提示删除事务边界。CREATE INDEX CONCURRENTLY 位于事务组内时同样提前说明不兼容。
- 执行记录分别保留 SQLSTATE、原始错误、事务组 ID 和事务结果。提交未获确定响应或结束后记录保存失败时，组内结果标为待核实，禁止自动重放；重启不会将未确认的组标为成功。

## 失败 SQL 切换账号重试（2026-10-22）

执行弹窗中的失败语句、SQL 详情以及失败清单提供“切换账号重试”。选择或输入数据库账号后，可使用已配置密码，或临时输入仅用于本次重试的密码。`postgres` 只读取独立管理员密码；其他账号按当前统一业务密码／账号专用密码方式读取，管理员密码与业务密码不混用。账号列表只返回名称和密码来源，不返回密码。

提交前先校验连接；失败时不取消原手动暂缓，也不提交 SQL。切换只作用于选中的失败语句；相邻视图 DROP/CREATE 配对失败时一起重试，显式 BEGIN/COMMIT 事务组从 BEGIN 整组重试，组外业务 SQL 不执行。文件的 schema、数据库目标和后续执行默认账号保留，未限定 schema 的对象以文件 schema 优先、保留所选账号连接原有 search_path 的方式查找；原脚本显式 SET/RESET 配置按已有会话恢复规则处理。恢复前置配置时不重放旧的 SET ROLE/SESSION AUTHORIZATION，避免覆盖本次选择的身份；事务正文中原有 SQL 仍按脚本执行。跨 schema 的限定名称仍由原 SQL 决定，不要求切换账号必须拥有原默认 schema 的 USAGE 权限，实际对象权限由 PostgreSQL 在执行时判定。

最新语句状态保存本次连接账号，历史分别展示数据库连接账号、文件 schema 和平台操作人。`RETRY_ACCOUNT` 记录本次账号选择及切换前错误；之后的执行尝试仍保留 SQLSTATE、原始错误和事务结果。临时密码仅存在请求／本次后台连接的内存中，不写入文件、执行选项、历史快照、审计或日志，也不更新已保存密码。成功语句不因切换账号而重跑；已删除文件、运行／排队中或结果待核实的事务仍受原有重试限制。

## 编辑整个 SQL 文件并保存（2026-10-22）

未执行文件列表的“编辑文件”，或执行窗口顶部“完整SQL / 编辑”中的“编辑全文”，可编辑并保存完整文件。保存调用 `PUT /postgresql/sql-files/:id/content`，携带当前全文及打开时的原始全文；内容发生并发变化时拒绝覆盖，并保留前端草稿。文件名、schema、数据库目标保持原配置，保存不连接业务数据库、不执行 SQL。

保存后按语句重新识别。未改动的语句复用原 ID 与执行状态，包括成功、跳过、失败暂缓和未执行状态；修改或新增的语句为待执行。重复相同 SQL 按出现次数匹配，已完成记录不会被重新置为待执行；成功／已跳过的 SQL 和完整事务组必须保留内容及已完成部分的相对顺序，修改／删除它们时指出原行号。显式事务按完整 BEGIN/COMMIT 组匹配，修改未提交组后整组待执行；失败的视图 DROP/CREATE 配对中一端被修改时，其失败伙伴也重置为待执行，保持组合事务重试。多个 ADD COLUMN 继续自动按字段拆分。需要时仅在原语句边界添加换行，保证原 ID 和新 ID 同时存在时的执行顺序正确；SQL 注释和函数体保留。

允许编辑未完成文件；运行、排队、已完成、整文件跳过或存在结果待核实语句时只读。可修复没有已完成记录的异常事务边界；已有完成记录且事务历史不一致时不猜测旧事务结果。

“修改历史”保留每次修改前／后的完整内容、修改人、保存时间和保存前语句状态与错误。旧执行尝试、视图备份、旧批次快照保持原样；被替换或移除的旧语句保留审计，不能再从旧记录直接重试。全文修改后从新的当前工作状态执行，历史批次不会被本次保存改写；新增 `FILE_EDIT` 文件级审计供 SQL 记录筛选。


## 文件分类、当前失败清单及视图任务联动（2026-10-22）

- “导入服务器文件”仅在全局参数 `customer_env=本地` 时显示，服务端导入接口同样检查；其他环境使用上传 SQL 文件。已有路径和大小限制保留。
- “未执行文件”只显示没有执行／处理经历的文件；“已执行文件”包括已发起执行、失败、中断、沿用历史结果和已跳过的文件。独立记录首次执行开始时间，续执行、编辑不清除；旧文件按执行批次、语句状态和历史记录识别，不将上传时间当成执行时间。
- 文件列表新增语句总数及成功、失败、未执行、跳过、待核实计数，显示执行成功、部分执行成功、执行失败、执行未完成、执行中、已停止及待核实等结果。已执行页保留查看／继续、批量继续剩余 SQL、全文编辑等入口；成功／已跳过语句仍受原有保护。
- 新增“失败 SQL”页签，`GET /postgresql/sql-failures` 查询当前目标库中有效文件的当前失败语句，包含手动暂缓；按语句 ID 返回一次，不把同一语句的多次失败尝试重复列出。编辑为待执行、重试成功或已跳过后退出当前失败清单。事务回滚的衍生结果不当作实际失败语句重复列出。历史失败尝试仍从执行记录查询；原按钮明确标为“历史失败记录”。
- `POST /postgresql/sql-statements/:id/view-dependency` 将失败的字段类型变更转入关联任务，创建源文件／行号／原 SQL 快照并固定目标库；重复转入返回同一任务。此操作只创建任务并暂缓原 SQL，不执行业务变更。任务页面可返回源文件，关联 SQL 不可在任务页改成无关联内容。
- 执行窗口支持同文件多选及“整文件转入视图依赖”，当前失败清单支持同文件多选合并转入；未执行的字段类型变更也可直接转入，无须先执行失败或逐条手动标记。`POST /postgresql/sql-files/:id/view-dependency/preview` 按原文件顺序返回可选择单元（单条 SQL 或完整事务组）和未纳入原因，允许取消勾选部分单元；成功、已跳过、已有任务及不支持的 SQL 不自动重置。提交到同路径去除 `/preview` 的接口时必须携带预览摘要及选择的单元 ID，重新锁定源文件校验目标、完整内容及处理状态；过期预览、跨文件、重复选择和已关联语句不能绕过检查。
- 批量任务使用现有事务执行器：按实际目标表和字段汇总、去重依赖视图，保留字段 SQL 顺序，统一删除／修改／恢复／校验后提交。每条原语句保留文件行号、原错误及转入操作审计；成功时统一回写各条结果，失败／结果未知不提前回写成功。一个原 BEGIN/COMMIT 组始终完整选择，且单独作为一个任务；不同原事务组及组外 SQL 不混成一个新事务。任务页面显示的字段行号对应原文件。
- 转入时保存源文件执行账号/schema 与前置会话设置的快照；分析时通过源业务账号的新连接恢复受支持的 SET/RESET 并解析实际搜索路径（包含原账号配置中的 public 或扩展 schema）。字段变更在管理员连接中使用该解析上下文，重建视图切回原管理员上下文，避免 USING 表达式中的未限定函数／类型解析到不同对象。快照不保存密码；源账号无法连接或前置设置不能安全恢复时明确停止，不使用管理员默认路径代替。支持 search_path、TimeZone、DateStyle、IntervalStyle 等标准解析设置；不同上下文须分别转入，SET ROLE、会话身份切换和临时 schema 不自动迁移。旧关联任务首次分析／执行时补建快照。
- 分析成功后即使依赖视图数量为零，也允许执行字段变更并回写源语句；执行前再次检查依赖与备份是否变化。页面将删除、恢复、检测视图显示为“无需处理”，没有视图备份时恢复按钮禁用。
- 关联任务使用事务执行，普通文件的其他未执行 SQL 可以继续；关联语句不能被普通重试、跳过、删除或全文覆盖绕过，任务活跃／结果待核实时阻止同源文件并发执行。任务分析、执行、恢复和成功回写检查目标库和原 SQL 身份。
- 同文件多个任务均为 UNKNOWN 时，可逐个恢复或校验，不再被其他 UNKNOWN 任务互相阻塞；恢复／校验仍与实际正在运行的任务互斥。普通分析／执行及成功回写继续拦截其他 UNKNOWN，不把恢复视图等同于确认字段变更已成功。
- 显式 BEGIN/COMMIT 仅允许完整、未完成、无特殊事务选项的纯字段类型变更事务组整体转入。包含 DML、DO、SET 或其他操作的混合事务、ROLLBACK 事务及已完成／结果不明的组拒绝拆出单句，保留原事务关系供人工审阅。
- 字段变更、依赖视图恢复和校验全部成功后，在同一平台数据库事务中保存任务结果、源语句成功状态及 `VIEW_DEPENDENCY_EXECUTE` 执行记录，并重新汇总文件状态。原失败尝试与旧批次快照保留。任务失败、恢复失败或结果未知时，不提前把源语句记成成功；失败清单展示关联任务状态和执行信息。
- `POST /postgresql/view-dependency-tasks/:id/cancel-transfer` 支持撤回未执行或已确认回滚的关联任务，源语句保留失败及暂缓状态，可再编辑／单独重试。执行中、已生效或结果待核实的任务不能撤回；撤回后原任务只读，不可再次变更数据库。
