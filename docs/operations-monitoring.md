# 主机监控、数据库诊断与巡检

监控和巡检分别运行：监控页面展示采样与数据库诊断信息；巡检中心将只读执行包下发到关联主机，回收结果后生成 HTML 和 PDF。

## 主机监控

主机管理中的“监控”提供 CPU、I/O 等待、内存、Swap、负载、磁盘容量与 inode、网卡吞吐及错误计数、磁盘吞吐、IOPS 和时延。支持单次采集或后台连续采集，间隔 30 秒、60 秒或 5 分钟。关闭页面不影响已启用的后台采集。

Linux amd64/arm64 执行器由构建脚本打包，通过已有 SSH/SFTP 连接按 SHA256 校验后缓存到登录账号的 `~/.dfops/inspection`。无需在目标机安装 Go、Python 或 exporter。首次连接固定 SSH 主机指纹，后续指纹变化会拒绝采集并显示错误。

采样保留 30 天。长时间范围返回最多约 600 个时间桶，每桶展示最后一个样本；缺失区间不补零，页面显示最近样本时间和采集错误。CPU/网络/磁盘速率来自两次约 1 秒间隔的计数差值。

## PostgreSQL 锁与慢 SQL 诊断

入口：数据库管理 → 锁与慢 SQL 诊断。数据库连接独立登记，也可以导入平台已有 PostgreSQL 连接。密码加密保存，接口不返回密码。

- 当前锁等待、直接阻塞者、根阻塞源、锁对象与等待起点：读取 `pg_stat_activity`、`pg_locks` 和 `pg_blocking_pids`。
- 当前执行超过 5 秒的 SQL：仅包含 `active` 会话，空闲事务显示最近一次 SQL，不将其时间当成当前 SQL 执行时间。
- 累计死锁：来自当前数据库的 `pg_stat_database.deadlocks`，同时展示统计重置时间。
- 历史慢 SQL、死锁详情和锁等待历史：从已有 PostgreSQL 日志增量采集。

诊断默认手动刷新，可选择 10/30/60 秒，仅页面打开时刷新。连接采用只读默认事务、5 秒语句超时和 1 秒锁超时；不会终止业务会话或修改数据库设置。当前会话最多 300 条、相关锁最多 500 条，达到上限会明确提示。

适用 PostgreSQL 14 及以上（使用 `pg_locks.waitstart`）。建议专用账号具备目标数据库 CONNECT 和 `pg_read_all_stats`；自动检测日志设置还需相应配置读取权限，例如 `pg_read_all_settings`。权限不足会显示提示，不把空结果当作无异常。

## 日志接入

在数据库连接中关联日志所在主机，点击“检测日志配置”，核对绝对目录、格式、时区与阈值，再启用日志接入。沿用数据库现有的 `log_min_duration_statement=5s`，平台不会修改 `postgresql.conf`，也不会重启 PostgreSQL。

优先使用 PostgreSQL CSV 日志。文本日志支持标准时间戳、PID 以及 DETAIL/HINT/CONTEXT/STATEMENT 多行关联；自定义前缀或不同语言日志可能无法完整识别，应通过原始日志核验。历史锁等待需数据库原已开启 `log_lock_waits`；未记录的事件无法补采。`pg_stat_statements` 的聚合统计不能替代逐次慢 SQL 日志。

后台约每 30 秒同步，单轮总读取上限 16 MiB，每文件最多读取 4 MiB；首次默认回溯 24 小时（可设 1～720 小时）。大日志按轮次追赶，可通过“读取进度”查看各文件已读字节及错误。读取游标和事件在同一事务提交，按文件设备/inode、截断代次、记录起始偏移去重，保留未完成的多行记录供下轮读取。支持重命名轮转和截断识别；源文件在读取前被删除的内容无法恢复。

页面提供时间、关键词、最低耗时筛选和分页，详情包含完整 SQL、账号、数据库、PID、客户端、应用、SQLSTATE、DETAIL/HINT/CONTEXT、原始日志和文件偏移。Parse/Bind/Execute 阶段分别保留，日志条数不等同于 SQL 执行次数。SQL 指纹当前为原文 SHA256，不是归一化模板。

日志事件保留 30 天。日志可能包含业务参数，应延用平台已有的账号访问管理与主机目录权限。

## 巡检中心与报告

支持手工批量选择主机和数据库，或配置每日定时计划。主机检查包括资源阈值和可选 systemd 服务；数据库检查包括实例身份、连接数、当前锁等待、当前慢 SQL、长事务、累计死锁，以及平台最近 24 小时已采集日志的统计和采集时效。

远端执行目录为登录账号私有目录，任务配置不出现在进程参数中，执行器读取后立即删除配置文件。执行包只读取资源与数据库状态；服务检查仅执行 `systemctl is-active`。

任务记录排队、下发、远端阶段、心跳、结果与错误；巡检并发上限 2。取消先发送标记，确认远端结果后再结束。SSH 中断后标记待核实，可读取原远端任务结果，不重复下发执行。平台重启通过租约恢复未结束任务。单个计划配置失效不影响其他计划，同一计划的上一轮未结束时跳过当日重复触发并显示原因。

采集结果和报告状态分别保存。检查完成可包含告警；权限不足、未配置日志或采集失败明确显示为未知。HTML/PDF 生成失败时，已采集结果仍保留，可单独重新生成报告。报告保存在工作空间 `operations/reports/run-编号`，下载需要平台认证。

PDF 使用原生 Go 排版和嵌入的 Latin 字体，并读取服务器上的中文 TrueType 字体；可用 `DFOPS_REPORT_FONT` 指定字体。兼容现有 DroidSansFallback 或 wqy-microhei 路径，无需 Chromium。缺少字体或字形时会显示报告生成失败，HTML 仍可下载。

## 编译与验证

使用 `bash scripts/build_dfops.sh` 构建。该脚本同时编译两个 Linux 架构的远端执行器、构建前端并嵌入主程序；直接 `go build ./cmd/server` 不保证包含执行器资源。

新增集成测试通过 `TEST_DATABASE_DSN` 指向可丢弃 PostgreSQL 数据库，`DF_ENCRYPT_KEY` 使用测试密钥。PDF 测试另需 `DFOPS_REPORT_FONT`。测试会建立测试表和锁等待，禁止指向业务数据库。

```sh
go -C backend test ./internal/opsprobe ./internal/pglog
go -C backend test ./internal/service -run '^TestOperations' -count=1
npm --prefix frontend run build
```
